# ADR-0008: 工作区信息架构——双栏分层、会话生命周期、.forge 元数据

- 状态：Accepted
- 日期：2026-08-25
- 关联：ADR-0007（每会话一区，本篇继承其地基）；journal s14；P29

## 背景 / 约束
P28 交付后用户指出三点结构性缺陷：1) 会话与工作区数量增长后无归档/删除生命周期；2) 当前会话工作区混在切换器里，不跟随会话在场；3) 文件列表是两级拍平而非真目录树，附件身份被硬编码在 uploads/ 路径上。约束不变：零依赖倾向、小白语义、变更成本最小。

## 候选与决定
1. **会话生命周期**：活跃 ⇄ 归档（`data/session-archive.json`，纯 UI 态）→ 仅归档组内可删除。删除首次弹完整后果说明（内存级标志 `delWarned`，每次打开页面重新提醒一次，不持久化）。删除会话不删工作区（区转孤儿，默认视野隐藏）。调度任务会话（session_type='scheduled'）永久过滤出列表，且桥启动时自动修剪只留最新 20 条（s14 事故：daily-mem cron 误配 `*/2 * * * *` 三天刷出 1765 条，把真实对话挤出 ACP 的最新50条窗口——已复位 cron 为每日 09:00 并清库）。
2. **右栏双 Tab**：「📁 本对话」= 永远跟随当前 sessionId 自动切换的目录树（无选择器）；「🗂 浏览全部」= 独立检索页（搜索/排序[最近|名称|体积]/状态片[全部|活跃|未关联|已归档]/每页30条客户端分页），默认片=活跃。
3. **真目录树**：递归结构（budget 400 节点封顶）；节点三型 file/dir/link；link=junction（外链目录与其他被引入的工作区统一概念），带源路径 tooltip 与 ✕ 取消引入；文件行操作 = 预览 / ↗ 本机办公软件打开(/open) / 🕘 版本时间线 / ✎ 重命名 / 🗑 删除（文件删前自动 snapshot 入 git，可经历史找回）。「＋文件」「＋目录」「只看附件(计数)」工具条。
4. **附件身份与路径解耦**：`.forge` JSON 文件存于每个工作区根部（listDir 天然跳过 dotfile），`attachments:[相对路径…]` 由上传端点写入、重命名跟随、删除清理；uploads/ 只是默认落点不再是身份。
5. **引入 = 相对引用语义的 junction**：目标为绝对路径存储（Node junction 限制），创建前 realpath 防环（禁止引进自身/祖先/后代）；删除工作区前扫描全库 junction 引用，被活跃区引用则拒绝。

## 否决项
- 应用内内容编辑器：否——内容修改是 agent 的职责，UI 只提供外部打开（/open 调系统默认程序）。
- 服务端分页：否——量级未到，接口形状留待需要时升级。
- 回收站：否——双重确认 + 文件级 git 快照已覆盖主要手滑场景。

## 后果
新增持久层两个 JSON（archive/.forge×N）；前端右栏复杂度上升但概念清晰（本对话 vs 档案柜）；junction 绝对路径意味着 forge 整体搬家后链接失效（接受：便携包解压路径固定使用，若将来需搬家改用 mklink /J 重扫或升级真符号链接）。

## 复核条件
- 会话数 > 数千且真实对话检索困难 → 会话搜索/标签。
- 工作区数 > 百级 → 浏览全部改服务端分页 + 归档冷存储。
- 出现整体搬家需求 → 处理 junction 绝对路径问题。
