# 闲时自主任务章程（idle-protocol）

> 本章程约束所有闲时自动拉起的团队工作会话。被拉起的会话（主控）开场必读本文件，全程遵守。

## 目标

团队在无人值守时段自主推进 PocketForge：自己找活、干活、验证、留痕。**产出可留痕的实质变化，禁止空转。**

## 启动序列（每次开场必做）

1. 读 `STATE.md`（现在）→ `AGENTS.md`（契约与团队）→ 最近 journal 1-2 篇（上下文）。
2. 检查工作树：有未提交变更 → 先弄清来源，陌生变更停下来记 journal 并跳过该文件。
3. 检查栈健康：bridge /healthz。栈不健康 → 尝试 `pc process restart chat-bridge` 一次；仍不健康 → 本轮改为纯文档任务（研究/审查），不碰运行时。

## 运行模型

闲时任务由官方算力调度：算力闲则继续，算力忙则自动暂停、下个闲时续作。因此：
- **无时间上限**——不设时间盒，活干完为止。
- **随时可断**——任务会被暂停/恢复切割，所以每个选题必须小步提交：完成一个可验证单元就 commit + journal，不留大量未提交改动（避免断点丢失上下文）。
- **恢复后重读**：每次恢复先重读章程与 STATE，检查工作树，再继续上次选题或重新选题。

## 选题器（按序找活，找到即开工；完成或卡住后回到 1 继续）

1. **待办池**：STATE.md 中标记 `[idle-ready]` 的任务（最高优先级，团队预审过的成活）。
2. **回归红**：跑 `tools/e2e/e2e-chat.sh` + `tools/e2e/fuzz-chat.sh` 全量。有 FAIL → 按 pf-qa → pf-dev 流程修复。
3. **bug 猎捕轮**：pf-qa 视角扩面——交互矩阵新组合、边界值、模糊测试新向量、GUI 回归手册未覆盖项。发现即修（小）或记 backlog（大）。
4. **backlog 顶层**：pf-pm 从 Backlog 选可独立完成项（无需真机/无需用户决策），裁决后派 pf-dev 实现 + pf-qa 验证。
5. **研究轮**：对标产品新动向 / goose 源码深挖 / 依赖行为验证。产出必须含「可执行建议」节，否则视为研究未完成。
6. **文档打磨**：回归手册、使用说明、research 底稿中过时或缺失的内容。

## 空转判定（硬性）

- 连续 20 分钟：无文件变更、无断言产出、无 commit → 判定空转 → 立即换下一个选题。
- 一轮选题全部尝试完毕仍空转 → 执行收束流程，正常结束。

## 收束流程（每个选题完成时执行，非会话末尾专属）

1. 全量回归：e2e-chat + fuzz 全绿（红了必须修完或回滚自己的改动）。
2. `STATE.md` 更新（现在状态）；journal 追加记录（做了什么/为什么/遗留）。
3. `git commit`（小步多次，message 引用 ADR/STATE 变化）。
4. **不 push 远程**（push 需用户确认）。**不动 data/ 用户数据**。**不升级依赖版本**。
5. 提交后回到选题器继续找活；全部选题层穷尽仍空转 → 正常结束，摘要末尾附：本轮选题、产出清单、遗留项。

## 需要跳过的情形（记 journal 后跳过，不硬干）

- 需要真机环境（妻子公司机）。
- 需要用户决策且 STATE 中无既定裁决依据。
- 需要新增依赖或许可（属 ADR 级决策）。
- 修不了的回归红（连续两次修复尝试失败）→ 回滚自己的改动并记 journal。
