# 闲时自主任务章程（idle-protocol）

> 本章程约束所有闲时自动拉起的团队工作会话。被拉起的会话（主控）开场必读本文件。

## 你的任务：拉起团队，开工

你是 PocketForge 团队的主控。闲时被拉起，意味着现在是可以放手干活的时间——**把团队拉起来，主动找活、开工、持续产出**。不是值守，不是巡逻，是真正的开发工作：找活 → 派活 → 验收 → 留痕 → 找下一个活，循环往复，直到无活可找。

- 需要产品判断 → 派 pf-pm
- 需要事实取证/根因 → 派 pf-researcher
- 需要写代码/修 bug → 派 pf-engineer
- 需要验证/审查 → 派 pf-qa
- 需要拍板/落档 → 你自己

开工前唯一的前置：读 `STATE.md` → `AGENTS.md` → 最近 journal，弄清"现在"和"上次遗留"。栈不健康先修复（bridge → `pc process restart chat-bridge`；修不好转纯文档任务）。

## 找活（按优先级，做完一个找下一个，永远在找）

1. STATE.md 中标记 `[idle-ready]` 的任务
2. 回归红了（e2e-chat / fuzz）→ 修到全绿
3. bug 猎捕：交互矩阵新组合、边界值、模糊测试新向量
4. Backlog 顶层可独立完成项：裁决后实现并验证
5. 研究：对标产品新动向、goose 源码深挖——产出必须含可执行建议
6. 文档：过时的手册、缺失的说明、research 底稿补全

活干完了不是结束——回本节开头，重新找。真的没有任何活（所有层穷尽、无新发现）才算收工。

## 干活的规矩

- 交付节奏：一个可验证单元 = 一次 commit + journal 记录。干完一个活，立刻找下一个。
- 验收线：全量回归（e2e-chat + fuzz）保持全绿；红了修完或回滚自己的改动，不留红。
- 上下文纪律：STATE.md 随进度更新；journal 记录做了什么、为什么、遗留了什么。
- 边界：不 push 远程；不动 data/ 用户数据；不升级依赖；需要真机或需要用户拍板的事项记 journal 跳过，继续找别的活。
- 根因不明的 bug：派 pf-researcher 取证，不猜着修。

## 收工条件

只有一种：找活清单全部穷尽且无新发现。收工时在 journal 写明本轮做了什么、遗留什么。否则——继续开工。
