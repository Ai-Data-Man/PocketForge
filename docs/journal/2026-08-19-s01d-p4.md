# 2026-08-19 s01d — P4/P4b 实现与验证

## 实现物
- `forge/启动数字员工.cmd`（CRLF ASCII）→ 调 `conf/bootstrap.ps1`（goose config 生成/secrets/端口探测/ports overlay）→ pc up 三进程。
- `forge/conf/process-compose.yaml`：nats（-js -sd data/js）/ faucet（--foreground 127.0.0.1 --data-dir）/ goose-scheduler（acp --enable-scheduler，依赖 faucet healthy）。
- `forge/conf/templates/goose-config.tpl.yaml` + bootstrap 生成 `conf/goose/config/config.yaml`。
- `forge/跟数字员工聊天.cmd`、`停止数字员工.cmd`、`使用说明.md`（妻子手册）。

## 踩坑记录（全部 VERIFIED-RUN）
1. cmd 文件必须 CRLF + ASCII（LF/UTF8 会把命令拆碎）。
2. pc YAML 值含 `${FORGE_ROOT}`（反斜杠展开）时必须**单引号**（双引号 YAML 转义报 unknown escape character）。
3. nats-server flags：`-js -sd <dir>`、monitor 是 `-m` 不是 `--http`。
4. **goose config.yaml 完全不展开环境变量**（cmd/args/envs/secrets 全部）——`${FORGE_AGENT_API_KEY}` 静默变字面量导致"Request timed out"假象（实际是请求发往坏 URL）；`${FORGE_ROOT}` 在 extensions.cmd 里同样失效 → 扩展静默不加载。解决：bootstrap.ps1 生成绝对路径 config + secrets 走真实环境变量（启动器注入 OPENAI_*）。
5. goose 扩展 schema 必须含 `name:` + `enabled: true`，否则静默跳过。
6. GOOSE_MODE=smart_approve 需交互终端；headless 用 auto。妻子聊天走 `goose session`（交互）无此问题。
7. goose config 布局：GOOSE_PATH_ROOT 下是 `<root>/config/config.yaml`（不是 root 直下）。
