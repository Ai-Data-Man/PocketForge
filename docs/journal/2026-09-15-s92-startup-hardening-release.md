## 教训

- #31 待入册：console 代码页污染链——任何 chcp（含启动器的 chcp 65001）会改共享控制台状态，影响后续同控制台内的 .cmd 解析；测试基建 wrapper 必须自带 chcp 936。
- 复核：`pg_log ready 行`做就绪判据 = 零连接成本的就绪门（优于 TCP 探活：端口先于「接受连接」可用）。
  **❗ 上条被发布门推翻（s93）**：受限令牌启动路径下 `data/logs/pg.log` **恒 0 字节**（postgres 输出进 pc 日志缓冲/pc.log，pg.log 只在停机时落盘）——据此做门 = 门永不开 → 备份崩溃零产出（QA F1 阻断项）。最终判据=**TCP 探活（bin/pg-probe.js）+ 1.5s settle**（跨 recovery 窗口）+ 显式状态返回。

## s93 发布门（独立 QA 两轮）

- **第一轮**（QA 独立复测，tmp/s93-release-gate-qa.md）：G2/G3/G4/G5/G7 全绿；**F1 阻断**=daily-backup 每次启动崩（就绪门读永不写入的 pg.log → 空串当成功 → statSync ENOENT）+ 零备份产出；F2=v0.9.12 旧升级器 R3 现场（文档化）；备注=应用模板无重启上限。
- **修复**：就绪门改 TCP 探活（backup+桥双处）+ 显式状态与存在性守卫（绝不抛异常）+ 模板 max_restarts: 3 + 发布说明补 F2 手动收尾两步。
- **第二轮**（F1 复验）：F1 六断言全绿（exit 0/两库 dump/zip 含 pg-dumps/降级边界）；**F3**=首启 12 行 `FATAL: database "forge_bridge" does not exist`（备份盲试 dump，桥建库比窗口晚 2-3s）→ 修=先 psql 查库存在再 dump（零 FATAL）+窗口 50s。
- **第三轮**（F3 定点复验）：4 棵全新树，两库 dump 首启即产出、停机后全日志零异常。
- 方法学入册（QA）：**pg.log 只在停机时落盘**——启动期日志扫描必须在停机后做终态复扫，否则漏 pg 侧全部内容（自测漏 F3 的原因）。
- 教训 #32 候选：容器/编排下的日志落盘时机与令牌上下文相关，任何"读日志判状态"的设计必须先验证该日志在目标路径真的会被写。
