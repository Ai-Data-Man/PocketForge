# 真机 POC 检查单（v0.9.9，在她电脑上过一遍）

> 用时约 15 分钟。每步"预期"不符时：拍照/截图 + 把 `data\logs\` 里对应日志一起发回，**不用自己排查**。
> 本清单同时是 EDR 清账项：企业杀软对 postgres.exe / pg_dump.exe 的态度只有真机能验。

## 0. 准备
- [ ] 拷 `PocketForge-20260905-v0.9.9.zip` 到她电脑，解压到**一个新目录**（如 `C:\PocketForge`；不要压在系统盘受控目录）
- [ ] 若机器上跑着旧版（v0.9.8）：先双击旧目录的「停止数字员工」

## 1. 首次启动
- [ ] 双击「启动数字员工」→ 黑窗口出现"[PocketForge] 启动中"
- [ ] **预期：这次首启比以往多等约 10-20 秒**（后台第一次初始化数据库，属正常，只发生这一次）
- [ ] 聊天窗口弹出，左上角绿点亮起

## 2. 基础冒烟（5 分钟）
- [ ] 随便发一句话 → 有正常回复
- [ ] 让她做一个真实小任务（如导一份零件清单做表）
- [ ] 任务产出文件 → 预览/下载正常
- [ ] 点侧栏下方的 **📮 反馈问题** → 弹出的报告里应有「小forge自己看到的毛病」节（系统正常时多为"没发现明显的毛病"）

## 3. PG（数据库）相关——本版新增
- [ ] `data\pg\` 目录出现（首启自动初始化）
- [ ] `data\pg.port` 内容 = 5432；`data\logs\pg.log` 里无 FATAL
- [ ] （可选）手动双击跑一次每日备份任务后，`data\pg-dumps\` 出现 `.sql` 文件

## 4. EDR / 杀软观察（本次 POC 的关键清账项）
- [ ] 杀软/EDR 是否对 `postgres.exe`、`pg_dump.exe`、`pg-probe.js` **告警、隔离或拦截**
- [ ] 注意区分：黑窗口如果提示 postgres 权限拒绝（"administrative permissions"）＝她用了管理员身份运行启动器——改用普通双击（资源管理器里双击）即可，不是 EDR 问题
- [ ] 若真被 EDR 拦：截告警图 + 拷 `data\logs\pg.log`，发回（设计上 PG 被拦不影响聊天/做表，只是数据库服务红）

## 5. 停止（本版修了真 bug）
- [ ] 双击「停止数字员工」→ 黑窗口走完正常退出
- [ ] 任务管理器确认：无 `process-compose.exe`、无 `postgres.exe`（本版之前它们从未被真正停掉）

## 6. 收尾
- [ ] 让她正常用几天；有怪问题点 📮 把报告文件发回
- [ ] `data\` 文件夹 = 她的全部数据；「换电脑」整目录拷走即可
