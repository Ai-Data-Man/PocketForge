# 对标景观扫描 → P32 设计输入（s78 支线）

日期：2026-09-13。验证状态：本文为 VERIFIED-DOC 级的公开资料综合 + 本产品实证对照；每条建议标注与 PocketForge 现状的差距，未验证项明示。来源=2026-09-12 web 扫描（Zapier/Reflex 2026 AI app builder 评测、Builder.io agent-native 架构文、agentic-design.ai 模式库、Baytech 内部应用商店蓝图、Gartner 2026-08 预测）。

## 0. 结论先行

三条对我们有用的方向，按「已有基础×差异化价值」排序：
1. **应用资产化**（agent 产出的数据/报表/应用成为可管理的资产）——我们已有 80% 基础（faucet 服务+@引用人话分组+制品工作区），缺的是「资产清单视图」。
2. **agent-native 对等架构**（人机共享同一套动作/数据/权限面）——我们已经是这个形态（faucet HTTP=人机同门），可作对外叙事与自查清单。
3. **生成式 UI 边界**（chat-first+工具卡 vs 自适应界面）——不建议跟进，与我们零依赖便携气质冲突。

## 1. 应用资产化（建议 P32 候选）

- 景观：2026 内部工具趋势=agent 按需生成应用并存入「内部应用商店」（Baytech 蓝图）；Replit Agent 等 prompt-to-app 产品把「产出物」当一等公民管理（列表/回滚/分享）。
- 我们已有的（VERIFIED-RUN，s78 主线测试两轮实证）：自然语言→建库建表（含 R4 人话说明）→数据→xlsx 制品→@引用可见→管理面板数据表清单→删除有确认。**链路是通的**。
- 缺口：**产出物没有统一清单**——数据表在管理面板、xlsx 在各会话工作区文件树、技能在商店，妻子视角「小 forge 给我做过哪些东西」无单一答案页。
- 建议（P32 候选，不立项）：「它做过的东西」清单视图（数据表+制品+已装能力三源合一，R2 分页+搜索，R4 人话名）。规模预期=护航期 <100 条。触发器=真机护航反馈里出现「找不回之前做的东西」≥2 次。

## 2. Agent-native 对等（叙事+自查，无需开发）

- 景观：Builder.io 提出 agent-native 架构=人类与 agent 共享同一 actions/data/permissions 面，反对为 agent 单开后门 API。
- 我们已是此形态：faucet HTTP API=桥 UI 与 agent MCP 同源；权限卡=人机同一审批点；@引用=同一数据目录。
- 用法：对外叙事（内测报告/发布说明可用此框架解释「为什么安全」）；对内自查=新增能力时先问「agent 与人是否同门」，防漂移。

## 3. 不跟进项（防扩张）

- 生成式 UI/自适应界面（agentic-design 模式库主流方向）：需前端框架与渲染层，违背零依赖便携+cmd 直启气质；我们的「工具卡+大白话解释」已是正确的轻量形态。
- 周期性 agent 自主巡检/心跳（多产品在推）：与 s78 健康探测裁决同一逻辑——无消费者场景的自动行为是浪费+打扰面，已裁掉。

## 4. P32 数据主权话术补强（已有 backlog 条目的素材）

- Manus 2026-08 数据删除事件仍是本地便携形态最佳论据；新增叙事角度：**「agent 产出的东西归你」**——数据表/db 文件/报表全部在 data/ 下可见可拷走（s78 测试实录：agent 主动告知 db 文件路径+删除范围），配合「资产清单」候选可成一套完整话术。
- 载体提醒（既有勘误）：项目须知.md 从未落库，届时先建文件再挂话术。

## 5. 元观察（学习方法）

- 本轮扫描的可用产出密度：15+ 来源 → 3 条可用 +2 条明确不跟进。对标研究的价值密度判断应在前 3 个来源后做，无增量即停——记入工作方式 backlog（研究类任务止损线）。
