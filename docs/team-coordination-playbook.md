# 团队协调手册（s78/s83 长会话实战沉淀，2026-09-13）

> 来源：单会话 40+ 子智能体批次（pm×4/researcher×9/engineer×17/qa×8）的调度实证。每条都有本会话的实锤案例。供后续长会话主控直接引用。

## 1. 套件窗口协议（最高频冲突源）

- **e2e 与 fuzz 不得并行**（s75 实锤，本会话三次再证）——谁跑全量谁独占，派工时明示「主控让出套件窗口」。
- **桥重启会打断所有在飞 GUI/WS 探针**：改 chat-bridge 模板的批次结束必 restart——派工时给并行方预告（本会话 SendMessage 预告制实证有效），或错峰。
- **真模型 GUI 测试（appcap 型）与 e2e/fuzz 不同时**：模型链共享 goose 进程树+会话号段。
- **会话号段是共享资源**：清理会话的批次（尤其连删≥2 顶号）会污染后续真模型测试（s83b 实锤）——自清后烧号已入探针；跨批次排序时把「删会话多的批次」放在「真模型验证前」并隔桥重启。

## 2. 同文件串行律

- chat-bridge.tpl.js / chat.tpl.html 是连续热区：**同会话内改这两个文件的批次必须串行**（PM 裁决书原话）。排队批次在任务书里写明「上游=xxx 已合流」。
- 提取型探针（rescue-guard/toolcard-frames/ui-logic 等 6 个）锚定模板原文：**改模板的批次必须核锚点**（先 grep 探针锚定区再动手），改了模板同步锚点；给探针加新符号（如 humanizeDecline）要同步提取桩参数列（ws-subscribe-race 桩 ReferenceError 实锤）。

## 3. 派工任务书模板（本会话验证有效的结构）

1. 角色定位一句 + 仓库/栈/端口/基线数（e2e/fuzz 当前值）。
2. 「先读」清单（裁决/报告/教训的精确路径）。
3. 修复规格（现象/根因/最小修法，或裁决切片）。
4. 硬纪律：全量回归必跑（签名教训）、物化链（bootstrap/cp+cmp+restart，别动 pg）、explorer 零开窗、假路由状态、自建数据清理（含句柄双源教训 #20）。
5. 留痕义务：journal/STATE 谁写（默认工程师写自己的，主控写全局——本会话两种都跑通过，明示即可）。
6. 「没做的事」清单义务（防夹带）。

## 4. 复审律（质量门）

- **每个实现批过 QA 独立复审**——本会话 8 轮复审抓到真问题的有 6 轮（P1 hello 竞态/P2 permission 丢卡/P2×2 掩码与 decline/3🟡 应用管理），零问题轮也有「核实通过」的证词价值。
- 复审任务书要点名 2-4 个「最可能的坑」（从实现批的自信声明里挑——「零锚点同步需求」「纯超集」这类断言是首选靶）。
- 负对照（修前模板打新断言必须红）是判别力证明义务——不是可选项。

## 5. 环境（云主机特有）

- 栈拉起必须降权：**PFdrill2 计划任务通道**（`schtasks /Run /TN PFdrill2`；runas 通道已死——s83 实锤，复活可回退）。僵尸态：先 `/End` 再 `/Run`。
- 提权 shell 里 pg 必 crash-loop（s66 家族，本会话三次）——一切「PG 段红」先查栈是不是被提权重启过。
- Bash curl 对本机端口有代理假响应（s66）——服务生死用 node 直连。
- explorer 窗口用完必关（用户令）；累积是常态（95 窗实录），每轮清点。
- 长会话 cwd 会重置——脚本用绝对路径或先 cd。

## 6. 留痕节奏

- 增量 journal（防中断丢记录——本会话 8 小时中断一次全靠已 commit 幸存）。
- STATE 顶部行由「当前在飞批次的工程师」随批轮替（本会话后期实证可行），主控负责全局收口段。
- 教训集（dev-lessons-s78.md #1-#22）随发现随入——它是唯一跨批次复用的「陷阱清单」，派工任务书引用条号比复述省 token。

## 7. 已知反模式（都付过学费）

- 睡眠值守（用户明令禁止——无产出轮次一律改为：全树验证/上游检查点/文档收口三选一的产出循环）。
- cron 巡检在本环境两轮零留痕（执行器疑似环境问题）——值守用主控轮内检查替代。
- 「顺手多修一点」（签名灾难 b4e02d2 就是死参数顺手删）——顺手项要么入任务书要么入教训，不夹带。
- 用 pm 角色跑纯测试任务（s83c 误派——能跑但角色错位，验收按产出不按角色）。
