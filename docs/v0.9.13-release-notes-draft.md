## s93 发布门修复（QA 独立复测阻断项，随本版交付）

- **F1 阻断（已修）**：出厂包  每次启动崩溃、零备份产出。根因=主控 s92 引入的就绪门读 ，而**受限令牌启动路径下该文件恒 0 字节**（实测：postgres 输出实际进 pc 日志缓冲/pc.log）→ 门永不开 → 耗尽后返回空串被当成功 → statSync ENOENT 崩溃。修=就绪判据改 TCP 探活（复用 ，FIN 半关零日志）+ 端口打开后 1.5s settle 跨过 recovery 窗口 + 显式状态返回（绝不再抛异常）+ dump 存在性守卫 + 耗尽=信息级跳过 exit 0。复验：冷启 2 轮 dumps/backups 双产出、日志零异常。
- **F2（已文档化）**：v0.9.12 旧升级器在停栈段随栈退出（R3），且旧升级器不认 apps/ 保护；发布说明升级路径已补手动收尾两步（QA 实测手动 runner done=True）。
- 顺手：应用模板补 （坏应用无上限重启会持续烧 CPU，QA 实测 3 分钟 restarts=31）。

## s90-s92 启动路径专项（用户实测驱动，全部实证修复）

用户连续实测报出启动期问题，逐一定位根因并修复（含独立复现实验）：

- **S-A 管理员双击数据库起不来**：内置 Administrator 账户双击 = 高完整性令牌（该账户 UAC 过滤不生效，实测），PostgreSQL 拒绝以管理员权限运行 → 桥降级「没连上数据库」。修=启动器检测到高完整性时**自动以受限令牌重开**（runas trustlevel，无需管理员权限），实测降权后 PG 进程正常、数据库接口 200。检测判据用「管理员组是否可用」——与 PG 自身的放行判据同源（完整性 SID 在受限令牌中仍存在，用它会无限重开窗口，实测踩坑已修）。
- **S-B 停止点不动/叉窗口无效**：停止命令未重定向 stdin、未禁用 TUI → pc 等待控制台输入而永不返回；pc 是独立进程，关启动窗口不会停它。修=停止脚本 stdin 加固 + 降级态（子进程已死而 pc 残留）强制收尾 + 失败时打印原因不再吞错。实测：正常运行中 <15s 全停，降级态也能收干净。
- **S-C 日志刷屏**：faucet 健康检查每 5 秒写一行 access 日志。修=探针改 TCP 探活（数据库同款先例），实测日志零增长。
- **S-D 每次启动的备份 ERROR**：备份任务与数据库/桥同时启动，撞「库还没建」与「数据库还没开始接受连接」两种首启时序。修=备份与桥均加**真就绪门**（等 postgres 自己写下 ready 再连，零连接成本），首启日志零 ERROR。
- **S-E 崩溃恢复满屏端口报错**：pc 被强杀后子进程成孤儿占着端口，再次启动撞 EADDRINUSE + FTL 洪流（且两个 pc 会共用同一份日志文件产生改名报错）。修=启动器预检（`conf/start-preflight.ps1`）：栈已在运行 → 友好提示「已经在运行」并退出；检测到孤儿 → 只清理本安装目录下的残留进程后干净启动。

## 给使用者的话（正文用）

这次更新主要解决五件你可能遇到或迟早会遇到的事：

1. **管理员账户双击也能用了**——以前在管理员账户下双击启动，数据库会起不来、窗口里说「没连上数据库」。现在会自动切到普通权限重启，数据库正常。
2. **「停止」按钮真的能停了，关窗口也有交代**——以前点停止没反应、叉掉窗口服务还在跑。现在停止一次到位（异常残留也会被强制收干净），关窗口的行为也有明确提示。
3. **放到中文文件夹也能用了**——以前把整个文件夹解压到带中文的路径（比如「桌面\数字员工」）再双击启动，窗口里会冒出奇怪的报错、数据库起不来。现在启动时会先用一句人话提示你换个纯英文/数字路径（如 D:\PocketForge），不再出现看不懂的失败。启动窗口里的中文乱码也一并修好。
4. **小 forge 搭的应用有了自己的家（🚀 小应用）**——以前让它给你搭一个应用（比如一个能打开的网页小工具），搭完就没地方看了：不知道开没开着、不知道从哪儿打开。现在 ⚙️ 面板多了一页「🚀 小应用」：每个应用一行，绿灯就是在跑，点「打开看看」直接进它的页面；没有网页入口的应用会老实说「它在后台做事」，不放打不开的链接。
5. **升级不会再把自建应用弄丢**——以前升级版本会把你已经注册的应用配置悄悄删掉。现在应用配置和你的数据一样受保护，升级后应用自动回来。

另外：启动窗口不再被健康检查日志刷屏、每次启动不再出现假的红色报错；崩溃/强杀后重新启动会自动清理残留进程再干净启动；换电脑/改文件夹名后「小 forge 记住的事」失联的问题修好了；安装包里不再混入开发机的临时文件。

### 升级路径
- PROTECTED 语义扩展：apps/（自建应用注册）自本版起升级零触碰；其余受保护文件口径不变。
- **v0.9.12 存量用户升级前必做**：手动备份 `apps\` 文件夹（整个目录复制一份）。原因：升级由旧版（v0.9.12）升级器执行，它不认识本版新增的 apps/ 保护，且**已知旧升级器在停栈段会随栈一起退出**（R3；新版升级器已修）。补救两步：①升级完成后把备份的 `apps\` 拷回原位；②若升级卡在「停止中」不动，先双击「停止数字员工.cmd」，然后在安装目录执行一次 `bin\pc\..\bin\node-v22\node-v22.21.1-win-x64\node.exe bin\update-runner.js --root . --staged <升级包解压或暂存路径>` 手动收尾（QA 实测 315s 跑完、done=True；栈会自动重启到新版）。自本版起跑的后续升级无此步骤。
- v0.9.10 及更早存量升级仍需手动备份 conf/goose/config/（同 v0.9.11 口径）；v0.9.11+ 存量直接升级。
