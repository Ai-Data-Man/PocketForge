# PocketForge v0.9.14 发布说明

更新日期：2026-09-16（s90-s94 工作会话产出；v0.9.13 因发布中止未与用户见面，本版并入其全部内容并叠加全面整改）。**发布包**：`PocketForge-20260916-v0.9.14.zip`（sha256 见随包 `.sha256`；与 v0.9.12 差量为文本/脚本/配置，exe 变更以包根 SHA256-EXE.txt 实测为准）。基线：e2e-chat 61/61 + fuzz 190/190 + appcap 13/13；**从零安装专项**：4 个全新沙盒三轮猎捕 + 出厂包终验（冷启降权/首配 GUI/真会话任务/重启持久/全功能面横扫，系统代理全开负例环境）。

## 这次修了什么（给使用者的话）

1. **「做过的东西」不再鱼龙混杂**——以前它把自己出厂自带的本领（看图、体检这些）也算成「给你做过的东西」，和真正的成果混在一起；数据表也在两页里各出现一次，分不清去哪页看。现在这一页只记它**在对话里真正替你干的活**（建的表、出的文件、它自己学会的本领），每条都能一键回到「东西住的家」去看内容、去删改；出厂本领回到「🧩 技能」页看。
2. **第一次配置服务商不再配不上去**——以前按提示「保存后再拉取模型」会拉到 0 个模型、保存也可能悄悄没生效。现在保存后拉取正常，没建档就保存会有一句人话提示。
3. **第一次让它干活不再卡死在「正在干活」**——以前如果电脑开着网络代理软件，它连服务商的通道会被代理吞掉，任务永远转圈、也不告诉你为什么。现在它自己绕开代理直连；万一还有问题，顶部会出现一句人话提醒「电脑上开着网络代理，可能拦住它连服务商」。
4. **全新解压首用，数据库一次就绪**——以前全新安装第一次让它建库存数据，它得先自己折腾一遍数据库钥匙（多花好几分钟，还可能把「做过的东西」页的人话说明弄丢）。现在安装包开箱自带全部钥匙，第一件事就直达。
5. **干活到一半界面不再僵住**——以前偶发它明明在干活（后台一切正常），界面却停在你发的那句话上不动了。修了两处会断流的根子；断线重连也会自动接上。
6. **它用的模型跟你勾选的一致**——以前第一次配置完，嘴上说切到了你勾的模型，实际还在用出厂默认的（碰巧能用所以没炸）。现在每次干活前会先对一遍账。
7. 并入 v0.9.13 已修：管理员账户双击自动降权、停止一键到位、中文路径预检、启动零红字、崩溃自动清理、🚀 小应用页、升级保护自建应用等（详见下文技术明细）。

## v0.9.13 中止版内容（s90-s93，首次随本版发布）

### 启动路径专项（用户实测驱动）
- **S-A** 管理员账户双击=高完整性令牌→PG 拒启→「没连上数据库」：启动器检测后自动以受限令牌重开（runas trustlevel）。
- **S-B** 停止没反应/叉窗口停不掉：停止脚本 stdin 加固+降级态强制收尾+失败打印原因。
- **S-C** 黑窗口日志刷屏：faucet 健康探针 http_get→TCP，30s 增量 0 字节。
- **S-D** 每次启动红色报错：备份与桥加真就绪门（TCP 探活+settle），13 轮冷启零异常。
- **S-E** 强杀后重启 EADDRINUSE/FTL 洪流：启动器预检（单实例识别+只清本安装目录孤儿）。
- **F1/F3（发布门阻断项）**：备份链就绪门改 TCP+psql 先查库存在再 dump——全新首启两库 dump 即产出、停机终态零 FATAL。
- **R1-R4（安装矩阵）**：应用聚合器粘行/模板转义/升级器随栈死（Start-Process 中介 spawn）/升级自备份补 apps/。
- 打包可复现：许可证改包内来源+zip 条目时间戳归一——同输入两次构建 sha256 一致。

## v0.9.14 整改内容（s94）

### 信息架构：「做过的东西」×「技能」返工（裁决 docs/verdicts/2026-09-15-made-ledger-ia-rework.md）
- **收录判据=对话产出**：数据表（带建库账）+ 工作区成品文件 + 自沉淀技能（origin=self）。出厂内置技能与市场安装技能永不入账——「做过的」=「有当时」。
- **台账/家分职**：台账只记账、带路（导航到各域既有入口）；表的家=「🗄️ 数据」，本领的家=「🧩 技能」，文件的家=右栏。同弹窗同实体唯一可操作清单。
- 分职母句进 UI 与使用说明；技能无说明时回落正文一级标题（不编造）。

### 从零安装缺陷修复（4 沙盒三轮猎捕，tmp/s94/findings.md）
- **F-2 (P1)** 首配「保存→拉取=0 模型」三因链（表单 key 安全清空×桥启动快照×401 映射空列表）→ 回落链接活跃服务商档案现读+非 200 诚实报错。
- **F-4 (P1)** 系统代理吞掉 goose 出网→回合永久挂起零反馈→spawn 注入 NO_PROXY（hyper-util 机理源码级验证）+ 代理人话告警条（探测 ok 但代理开也保留）。
- **F-6 (P1)** 全新装机 faucet 零供给（无 admin/key/.apikey，台账人话名/时间/来源静默全空）→ bootstrap 种子+首启 oneshot 幂等供给三件套。
- **F-11 (P1)** 回合渲染流冻结双向量（热重启清订阅集不重建；**ws 掉线重连不重订阅**——回合帧被静默丢弃而广播帧仍达）+忙碌态泄漏 → 订阅集随绑定重建+重连即重订阅+断线清忙碌。
- **F-1 (P2)** 服务商表单陷阱（未建档保存静默无效/添加清表单）→ 人话提示+Key 栏保留+双渲染根治。
- **F-3 (P2)** 首配宣称切模型不生效（模型随 spawn env 钉进会话）→ prompt 前会话模型对账+同 env 热重启抑制。
- 小项：台账日期 08:00 显示（UTC 解析+8h→本地零点+越界日期不编造）；@菜单不再漏出建账系统表；.apikey 永缺时诚实降级标记；启动器窗口正常停栈后自动关闭（原残留占目录）；停止后零窗口残留。

## 给 IT/懂电脑的人

- 本包无数字签名。Windows Defender「低流行度+新文件」可能对新解压程序弹提示——按包根 **SHA256-EXE.txt**（全部 exe 哈希清单）向 IT 登记即可。
- **代理环境**：若机器常驻代理软件（Clash 等），本版起 agent 出网自动对活跃服务商主机直连（NO_PROXY 注入），无需再关代理；健康探测在「探测通但代理开着」时仍会提示，供排查参考。
- 管理员账户双击启动已支持（自动降权）；非 ASCII 安装路径仍会被预检拦截并提示（PG 上游限制）。

## 升级路径

- **v0.9.12 存量用户升级前必做**：手动备份 `apps\` 文件夹（整个目录复制一份）。原因：升级由 v0.9.12 的旧升级器执行，它不认识本版的 apps/ 保护，且已知旧升级器在停栈段会随栈退出。补救两步：①升级完成后把备份的 `apps\` 拷回原位；②若升级卡在「停止中」不动，先双击「停止数字员工.cmd」，再执行一次 `bin\node-v22\node-v22.21.1-win-x64\node.exe bin/update-runner.js --root . --staged <升级包路径>` 手动收尾。自 v0.9.13+ 桥发起的升级（含升级前自备份含 apps/）无此步骤。
- v0.9.10 及更早存量升级仍需手动备份 conf/goose/config/；v0.9.11+ 存量直接升级。
- v0.9.13 无存量用户（发布中止），无需考虑该路径。
