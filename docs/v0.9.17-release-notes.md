## 这次修了什么（给使用者的话）

1. **它干活时，你看得见它在干嘛了**——以前发一句话过去，界面就只剩三个小点点转半天，不知道它在想还是在动手、要等多久。现在下方会有一行字：它现在**是在想、在动手还是在写答案**，已经花了多少秒；想得深的时候还会写着「它正在尽全力想」——要是嫌慢，看一眼上面模型名字旁边的「思考力度」，调浅一档下次就快了（使用说明里也补了这句引导）。
2. **能看它的思考草稿**——有的模型会一边想一边说草稿（中文环境常见的 glm 系要等上游线路支持才显示）；有草稿时那行字旁边会出现「看看它在想什么 ▸」，点开能看它想的过程，想完自动收起来、不留在对话里。
3. **对话窗口里不再冒「断了」之类的奇怪东西**——修了四类张冠李戴：网络其实好好的，只是服务商回话慢了一拍，以前会误报「服务商不通」还插到对话里（现在只有顶栏状态点说话，而且要连续两次确认才算真断）；它自己回复里带了「限流」之类的字样，以前会被当成出错（现在只有真出错才算）；软件重启时正在干活的步骤以前会标成红色「失败」（其实只是结果未知，现在如实说「连接断了，这一步的结果不确定」）；删掉当天最新的对话后马上再切换模型，以前偶尔会提示「切换失败」（现在会自动换到新对话完成切换）。
4. **测试和拉取模型有记录了**——⚙️ 设置里「测试连通」「拉取模型列表」以前做过就忘（出问题时查无此账）；现在每次都留一行记录（连的哪家、通没通、花了多少秒）。出问题点 📮 反馈时，这些记录会自动进报告。
5. **反馈报告能抓住有效信息了**——📮 报告新增四段：每一次模型请求（什么时候、用的哪个模型、想多深、花了多少秒、成没成）+ 最近做过哪些操作 + 软件自身的近期日志 + 最近七天模型使用统计。以前报告只能看出「环境大概健康」，看不出「你刚才那次到底发生了什么」。
6. **钥匙更安全了**——修了一个潜在漏洞：个别中转服务在报错时会把你的钥匙原样带回，以前这种报错原文可能进日志和反馈报告；现在日志和报告在写入前就把钥匙内容打码，无论对方怎么回显都带不出来。
7. 并入 v0.9.16 全部内容（思考力度官方档位全链路/设置三分类/模型能力可修正/首启 daemon 根治，见 v0.9.16 说明）。

## 技术明细（按域）

### 主线1：慢会话过程可见 + 断线异常 UI（s103，裁决 docs/verdicts/2026-09-25-slow-session-observability-fix.md）
- **根因**（research/44）：慢不在桥（llmproxy 零可测延迟、switch 201ms、session/new 2-3s）——分钟级耗时=思考期本身+默认档放大器（新会话无档位习惯时按官方预置 default 注入，flash 系默认 max/high）；过程黑箱=前端刻意丢弃 `agent_thought_chunk`（keep silent）；断线 UI=四条独立通路。
- **S1 忙碌条三要素**：阶段由「等模型响应窗口→首个工具调用/正文帧」推导（对所有模型统一；QA 发现现行配置 goose 对全部非 gpt-5 系 0 thought 帧，信号源从帧换轨为响应窗口——主控修订裁决 3.1）；秒计时；档位人话复用 THINK_LABELS 单一真相源。deepseek 无帧=只有阶段+计时，不造假象。
- **S2 思考草稿面板**：32KB 显示尾窗、回合结束即弃、不进聊天流不落库；仅上游有 reasoning 流时出现。
- **S7 健康条退出聊天流+去抖**：健康类瞬时态永久退出消息流（顶栏承载）；down 需连续 2 次失败确认、探测超时 8s→15s（/models 实测 1.6-9.1s 横跨旧阈值=慢≠不可用）。
- **S8 S26 收窄**：判定门收到错误报告头冠正则（活测五臂定门：SSE 错误体=goose 头冠整轮文本/401=既有 reject 路/中途断流=残正文）；成功回合零计数零复检零💡卡；真错误臂三路保持。
- **S9 中性收口**：重启时进行中工具卡置 unknown 态不翻红。
- **S10 sid 毒号止血**（research/46 RCA）：删当日最新会话→goose 按「当日 MAX+1」发号复用刚 close 的 sid→closed 集只增不减→新会话出生即死（六环链源码级+六臂活体；救援守卫按 sid 继承形成仅重启可解的死锁）。修=出生清救援守卫+切换死绑定走既有代开重绑路径（零 goose 改动）。backlog：救援轮补钉模型、goose 发号避死集。

### 主线2：观测性（research/45 矩阵 G1-G14）
- **通道选型定案**：桥 console.log→pc.log 受冲刷限制不可靠（8h 无新行实证）——产品观测恒走 appendFileSync 直写。
- **S3 events.log**：test_model/list_models 每次一行（host 脱敏/http/耗时/错误摘要）+providerTests.{ok,fail} 计数（用户点名两操作零留痕→6s 内盘上有痕，探针反转实证）。
- **S4 llmproxy 全请求行**：别名+非别名同格式（ts/model/effort/首字节ms/总ms/状态码/path/错误摘要）——LLM 主路径生产静默根治；两日志 5MB×3 轮转（写前查大小）。
- **S5 运维事件行**：providers 变更/switch from→to/set_think/hotRestart 触发源/健康探测（state/kind/耗时/连续失败计数）全落 events.log。
- **S6 📮 报告补读四节**：llmproxy 尾 30+events 尾 50+ring buffer 尾 50+usage_ledger 近 7 天聚合。
- **安全收尾（QA 边界测绘驱动）**：非 sk 形态 key 外带堵口（写入侧 sanErr 四形态+报告黑名单兜底）→恶意中继裸值回显结构性盲区根治=**值域脱敏**（sanErr 增参收该请求真实 key，split/join 纯字面替换防 $& 反噬，≥8 字符边界）+黑名单补 x-api-key/api-key/apiKey 三形态纵深。攻击臂 0 泄漏（QA 独立仪器复验）。
