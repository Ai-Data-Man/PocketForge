# 裁决书：ADR-0011 阶段二（自建应用首选库——首个消费者）设计与验收

- 日期：2026-09-05 / 裁决人：pf-pm / 执行：pf-engineer
- 输入：ADR-0011、research/10（pg_dump 来源已解：EDB zip 子集 0.59MB，dump 实测通过）、STATE.md（s66 阶段一遗留）、tmp/scale-inventory.md（主控 s66 盘点）、chat-bridge.tpl.js 存储段现状（atomicWrite/readJson JSON 单写者模式、STATE_SCHEMAS 注册表、stats 防抖异步写、会话硬删直改 sessions.db）
- 边界声明：全部裁决在 ADR-0011 Accepted 方向内（PG = 自建应用首选库）。裁决内容是对阶段二范围的再收窄，依据是 scale-inventory 的新证据；方向不变，内容重划。

## 0. 核心裁决
阶段二 = 立轨 + 导出先行，零数据迁移、零业务消费者、零 bridge 存储改写。首个消费者选 d（新应用默认 PG 的轨），并把它从"一句纪律"做成"有实物、可验收、可独立回退的运维切片"。
- a 消息检索索引：拒绝，归阶段三（"用户点名痛点"未证实——用户原话点名的是 PG/正经后端不是搜索；scale-inventory 实证妻子量级 LIKE 毫秒级无感；同步漂移=已删会话出现在搜索结果=正确性+隐私双重缺陷）
- b 工作区/制品索引迁 PG：拒绝，转触发制（零痛点，动正在工作的存储=纯变更成本）
- c 使用统计迁 PG：拒绝
- d 立轨 + 导出先行：采纳（保险价值真实可实物化；改动面约 30-40 行）
裁小依据：迁任何旧数据都是在"痛点不存在"的证据上做迁移工程。但导出先行提前到今天=ADR-0011"默认导出路径先行"的字面执行，空集群上演练免费。

## 1. 轨道内容（四条 doctrine，本裁决起生效，落 STATE）
1. 新存储默认 PG（ADR-0011 继承）：每应用一个 database（forge_<app>），禁止跨应用共享写。当前无新存储需求，本条是纪律不是代码。
2. 首行业务数据三件套同提交：客户端入树（vendored）+ PG schema 迁移注册表 + 恢复工具入树（pg_restore 或 psql，EDB 同源子集约 +1.55MB）。空库阶段不预置。
3. 导出先行恒在：pg_dump 每日随 forge-backup 链自动执行，先于任何数据存在。
4. 消费方失败面闭合集：任何 PG 消费者必须声明 PG 不可用时行为，三选一——(i)回落文件（有损容忍）(ii)降级禁用+人话提示（功能型）(iii)论证必须持久后方可无回落（默认否决）。连接纪律：lazy 连接、connect 超时 ≤2s、桥零 depends_on 指向 pg。

## 2. pg_dump 进树与备份接线
- 来源：EDB 官方 zip 17.11-1 子集，只取 pg_dump.exe 单文件 +0.59MB；pin -1 rebuild；zip sha256 护栏（6eabdf00…）。fetch.sh 增一步：下载 zip → 校验 sha256 → 抽取 pg_dump.exe → 断言 zip 内 8 DLL 与树内哈希一致（把"同源"变成每次 fetch 的可复验断言）。
- 版本耦合 doctrine：pg_dump 与 server 主版本同步换版，随 PG 升级重做哈希。
- 备份链：forge-backup.js 打包前增 pg_dump 步骤——bin/pg/bin/pg_dump.exe -h 127.0.0.1 -p <data/pg.port> -U postgres -d postgres -Fp，plain SQL 落 data/pg-dumps/pg-<ts>.sql，keep 3；data/pg-dumps 加入 SOURCES 白名单，随每日 zip（keep 7 不变）。plain SQL 不选 -Fc：零技术背景可读，体积无差别。
- 范围边界：阶段二只 dump postgres 库（空库）；多库枚举随三件套落地。pg_dump 失败 = warn 一行进 backup.log，zip 照常产出。
- 报告 v2 零新增 PG 节。

## 3. 随批修复：readiness 探活去假阳性（阶段一遗留 ②）
pg_ctl status 信 postmaster.pid，s66 实证 stale pid 下 restarts 耗尽面板仍 Ready。探活改 TCP 复核（readiness_probe exec 用树内 node 一行 net.connect 探 data/pg.port）。约 2 行 yaml + 决定性实验留痕。超 10 行即砍出切片另排微批。
明确不翻转：重启策略维持 on_failure+max_restarts:3；trust 认证/max_connections=20 维持（随首个消费者复核）。

## 4. PG 客户端选型（定案，不入树）
Pin：postgres.js 3.4.9（Unlicense）。理由：许可证字面落公有领域类；无传递依赖（待取证）；纯 JS 零编译。pg 8.23.0（MIT）为后备（触发：postgres.js 撞能力墙或依赖取证不过）。入树时点=首行业务数据同提交。本阶段只做本机取证（VERIFIED-RUN 进 research/10）：npm --omit=dev 拉取、依赖树清点、CJS require 可用性、对运行中 PG 17.11 连接/查询/UTF-8 中文往返/错误路径/connect 超时 2s 断言。取证不过切 pg 8.x，无阻塞。

## 5. Schema 纪律：ADR-0009 映射到 PG（阶段三/新应用直接沿用）
每应用库内置 schema_migrations（version,name,applied_at）；代码侧有序 MIGRATIONS 数组=注册表。启动时 lazy：PG 可达才跑。顺序幂等、forward-only、事务包裹；迁移前先跑一次 pg_dump 再 apply（导出先行复用为迁移保险）；降级守卫：库内版本新于代码 → 拒写该库 + UI warning。本阶段只落 doctrine 文本。

## 6. 失败面
零业务消费者故"PG 失败=栈照常绿"自动成立，新增实证路径：备份链在 PG 死亡时仍产出 zip。桥零 pg 引用、yaml 桥零 depends_on 指向 pg 两个"0"是阶段三不许破的底线。

## 7. 回退阶梯
L0（本阶段起恒可用）：删 data/pg + bin/pg + forge-backup 三行 = PG 完全卸载。
L1（出现数据后恒可用）：pg_dump 导出（每日自动+升级器前置一次）→ 按消费方回落重建 → 执行 L0。导到哪：data/pg-dumps/ → 每日 zip。多久：每日 + 迁移/升级前强制。

## 8. 阶段三门槛（现在定死）
1. 同步机制：桥侧 ACP stop 事件增量索引为唯一正触发；启动时差异对账兜底；桥硬删会话路径必须同步删索引（正确性+隐私双重红线）。
2. 检索入口：PG 可达走 PG 全文，不可达回落既有 LIKE 路径（回落今天已存在，边际成本≈0）。中文分词留阶段三取证。
3. 隐私结论：会话正文进 PG = 隐私面扩大成立。放行条件：删除传播设计 + welcome/项目须知存储描述更新。不满足即否决。
阶段三触发器（满足其一才开工）：真机消息量逼近 1 万；或妻子对搜索的真实负反馈。否则无限期挂起——这是 feature 不是地基。
