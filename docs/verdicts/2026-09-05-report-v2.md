# 裁决书：小forge 可观测增强 + 一键上报增强 + 初步诊断（P31 附加轮，s64）

## 一、三次为什么锚定真问题

**一问：为什么要增强可观测+一键上报？**
用户给的是方向（"信息全面性+初步诊断"），不是问题。还原场景：妻子遇奇葩问题 → 点 📮 → 把 md 发给丈夫 → 丈夫读报告 → 猜 → 给一步指令 → 妻子执行 → 可能再来一轮。这是一个**异步支援回路**，瓶颈不是"报告信息不全"，而是两个数：**丈夫从打开报告到形成第一个可执行假设的分钟数**，和**支援回合数**。堆原始数据不缩短这两个数——pc.log 尾部 300 行丈夫本来就有，缺的是人话。

**二问：为什么现在慢？**
（a）丈夫每次都要人工把同一批信号（faucet 探活、key 配置、401 计数、端口占用、代理）翻译成故障假设——这些翻译知识在用户脑子里，没有外置；（b）报告全原材料，没有结论层。"初步诊断"的本质 = 把硬核用户脑内的确定性翻译规则外置成代码。这不是"智能"，是"查表"。

**三问：为什么不让小forge（LLM）直接诊断？**
（a）**agent 挂掉恰恰是生成报告的主场景**——被诊断对象不可用时，依赖它的诊断也不可用；（b）LLM 输出不可控，小白照做不可控动作与"克制"基调直接冲突；（c）内测期零遥测，任何"智能诊断"都无法验证收益。所以"有用但克制"的操作化定义只有一种：**规则式、离线、确定性、只说不做**。

**锚定结论**：本轮交付物 = "丈夫 3 分钟内形成首个假设"的报告 v2。不是可观测平台，不是智能诊断。

**三角判据**（信息效率 vs 体积 vs 隐私）：每个新增字节必须回答"丈夫看到它能排除哪种故障"。答不出的不采集。隐私按既有黑名单做延伸解释（见第四节），体积 256KB 硬顶（见第六节）。

## 三、明确不做什么（裁掉项+理由）

| 裁掉项 | 理由 | 去向 |
|---|---|---|
| LLM/小forge 自动诊断 | 三问已答：被诊断对象不可用时不可用；输出不可控；零遥测无法验证。与"克制"基调正面冲突 | P32+，需真机护航实证规则不够用 |
| goose"真干活"探活 | 需 LLM 往返或深耦合 goose 内部结构，超"最小 diff"边界。本轮以弱信号替代（最近会话活动时间 + pc.log 中 goose 相关错误行，报告已含） | P32，若护航实证"探活≠能干活"高频误导再立专项 |
| 报告自动外发（邮件/上传） | 需网络通道+扩大隐私面；"发前自己翻"的人工闸门是特性不是缺陷 | 无限期搁置，除非用户回线提出 |
| 丈夫远程拉取报告 | 重大架构变更（网络通道+鉴权），内测期单用户场景收益不成立 | Backlog |
| 定时任务名称/id/cron 入报告 | 无实证调度诊断需求；名称由自然语言派生=私人内容（"周三提醒老公吃药"风险实锤存在——yaml 里 title+instructions 同源）。两个计数数字已够远程分诊 | P32，调度诊断需求实证后再议白名单化 |
| 技能名称清单入报告 | s05 技能自进化=技能名可由对话派生，同定时任务名风险；无实证诊断需求 | P32 |
| 磁盘剩余<1GB 诊断规则 | 采集入（A2 便宜），但规则不放行：内测至今零实证故障族，不满足准入门槛 2 | P32，等第一次实锤 |
| reports/ 目录清理策略 | 每次生成新文件会堆积，但单用户低频，未成痛 | 观察项记 STATE，不成待办 |

## 四、隐私边界逐条裁定

| 项 | 裁定 | 理由（摆上台面的取舍） |
|---|---|---|
| secrets.env / conf/goose/config/memory/ / 会话消息正文 | **维持黑名单，绝不读取** | 既有硬约束不动 |
| 定时任务 schedule.json | **仅条数+暂停数**。不读 id、title、cron、scheduled_recipes yaml | title/instructions 由对话派生属私人内容；id 为同名派生 slug 同源风险；无实证需求撑不起隐私面扩大 |
| 技能 | **仅数量** | 自进化技能名同上；收益仅一条上下文，不值 |
| MCP | **名称+enabled 入；env/cmd 参数与任何值绝不入** | 名称来自精选市场（目录 3 项+fetch），非私人；挂载失败有实证故障族。注意 goose config 的 mcp-* 块常含 env 形态的 key，必须结构级排除（见验收 4），不许依赖 reportSanitize 正则兜底 |
| 系统代理 | **ProxyEnable/ProxyServer 入**（注册表只读，不违反零污染——零污染禁的是写） | 开放问题 3 实证在案；ProxyServer 可能暴露内网代理地址，读者为受信丈夫，风险可接受，特此留痕 |
| data 体积 | **只有合计，无文件名明细** | ws-* 目录名派生自会话名，文件名罗列=变相元数据泄露，且对诊断无增量 |
| 会话元数据一行 | 维持现状（s61 已裁定过） | — |

**总原则**：本报告的隐私模型 = "受信技术亲友可读"，黑名单防的是"公开（GitHub issue）不可读"。凡存在公开路径（issue 模板在报告内），新增项按公开标准过滤。reportSanitize 仍是写盘前最后一道兜底，不是设计依赖。

## 五、诊断规则准入门槛 + 本轮准入规则

**准入门槛（四条同时满足才配成为一条规则）**：
1. **信号确定性**：布尔/计数/正则可判定，无模糊推断；
2. **实证故障族**：真机/内测/开发期实锤≥1 次，或 STATE 开放问题在案——直觉和"可能会"不算；
3. **动作小白可独立完成**：单一动作（双击/点按钮/发文件），无破坏性（不引导删数据/手改配置文件）；
4. **误报无害**：措辞不恐慌，永远留"没解决就把报告发出去"的出口。

**本轮准入规则表**（每条独立函数+单测，禁止在模板里堆 if；文案落常量表）：

| # | 信号 | 输出大白话（形态） |
|---|---|---|
| R1 | faucet 探活未响应 | "数据库服务没起来。建议：双击桌面的『停止数字员工』，再双击『启动数字员工』，然后重试刚才的事。" |
| R2 | providers 全部未配 key | "数字员工还没有配『钥匙』。建议：看聊天窗口顶部的引导条，点它去配。" |
| R3 | 最近 7 天 unauthorized 计数>0 | "最近有『钥匙失效』的记录。建议：到设置里把模型钥匙重新配一遍。" |
| R4 | pc.log 尾部含 EADDRINUSE | "启动端口被别的程序占了。建议：重启电脑后再双击启动；还不行就把这份报告发给帮你的人。" |
| R5 | 系统代理开启 且 7 天 upstream 连接错误>0 | "电脑开着代理，最近也有连不上网的记录，可能有关。建议：把这份报告发给帮你的人判断，先不要自己改代理设置。"（R3 联动去重：同一信号不重复触发） |

**明确形态约束**：每条 = "现象+建议+出口"三段；R5 的动作就是"发报告"，因为改代理不是妻子该做的事——规则不许引导用户做有副作用的操作。

## 六、体积预算

- **硬顶 256KB（写盘后文件大小）**，与 reportTail 既有 256KB 读预算对齐为单一常量（建议 `REPORT_MAX_BYTES = 256 * 1024`，一处定义两处引用，不做两套数字）。
- 超顶时**按节截断**：先截日志节（pc.log→backup.log→统计 JSON），保留全部结构化短行与诊断节；被截节末尾加"（已截断）"标记。
- 预期 p90 约 30–60KB：微信文件零压力，人能翻完，issue 粘贴环境节不爆。
- 本轮新增采集全是 KB 级短行，膨胀源仍是 pc.log，已有 256KB 帽——预算是保险丝，不是常态路径。

## 七、成功指标（观察窗口：真机护航期，随下次用户回线收口）

1. **主指标**：远程支援回合数下降——同一问题"发报告→解决"的往返≤2 轮（用户回线定性确认即可，内测期 N=1 不做定量装样子）。
2. 诊断规则命中率：真实报告中至少一条规则命中且用户确认相关≥1 次；或连续护航无命中且无新增故障族 → 规则表冻结不再加。
3. 反向指标（出现即回调）：报告因体积被微信拒收/用户抱怨"太长不想翻"≥1 次 → 触发预算与日志节复审。
4. 隐私零事故：用户回线未出现"报告里有我不想让别人看的东西"。

## 八、pf-engineer 验收清单（可断言）

1. **节序断言**：报告含「小forge自己看到的毛病」与「快速判断」（A7 汇总行）节，位于生成时间行之后、环境节之前。
2. **脱敏断言（写盘文件级，非内存级）**：fixture 注入 `sk-`/`ghp_`/`gho_`/`github_pat_`/`AIza`/`glpat-`/`xoxb-`/`GH_TOKEN` 形态（providers.json 与模拟 pc.log 行两路），对落盘 md 断言上述形态 0 命中、命中行呈 `<已脱敏>`。
3. **零正文断言**：fixture 在 scheduled_recipes yaml 注入 title"周三提醒老公吃药"与 instructions 标记串，落盘报告 0 命中；报告仅含"定时任务 N 个（暂停 M 个）"形态行，且 id `daily-mem` 与 cron `0 9 * * *` 字面 0 命中。
4. **MCP 结构级排除断言**：fixture 在 config.yaml mcp 块 env 放 `sk-` 形态 key **和一个不匹配任何脱敏正则的自定义值**（如 `TOKEN_xyzzy@1`），落盘报告两者均 0 命中——证明排除靠结构（只渲染 name/enabled），不靠正则兜底。
5. **A3 预算断言**：膨胀点统计对注入的万级小文件临时目录 2s 内返回，或输出"统计超时"；报告只有字节合计与文件数，无任何文件名（fixture 断言）。
6. **规则单测**：R1–R5 各≥1 正例+1 反例（faucet 存活→R1 不触发；有 key→R2 不触发；unauthorized=0→R3 不触发；无 EADDRINUSE→R4 不触发；代理关→R5 不触发）；文案常量表每条含"建议"与"报告发给帮你的人"出口语。
7. **体积硬顶断言**：构造超 256KB 场景，落盘文件 ≤256KB 且含"（已截断）"，诊断节与环境节完整保留。
8. **回归**：e2e 33/33 + fuzz 44/44 全绿；现有八节（环境/日志/备份/统计/providers/会话概况/补充说明/issue 模板）逐节存在断言；explorer /select 弹出选中行为不回归；fuzz 白名单同步更新。
9. **零污染断言**：本轮新增读取仅限注册表只读（ProxyEnable/ProxyServer）与白名单路径读；除报告文件外无任何写操作出 data/。
10. **最小 diff 自检**：buildReport 内增量实现，MCP 读取复用 /api/extensions 既有函数，不新增端点/新文件/新依赖。

## 九、规模控制声明

本轮 = buildReport 一个函数族的单向增强 + 5 条查表规则 + 1 个常量。无新端点、无新文件、无新依赖、无 UI 改动、无重构。拖到 P32 的：goose 真探活、定时任务诊断、磁盘规则、技能名称清单、LLM 诊断、调度白名单化——全部已有明确回触发条件（护航实证），不是"以后再说"。

**给主控的派工边界**：本裁决书即验收基线；pf-engineer 若发现某条规则信号在现有采集下不可稳定取得（如 R5 的 upstream 错误口径），按"砍规则不砍采集、砍采集先回报"的顺序降级，不得自行放宽隐私边界或引入新读取面。
