# 裁决书：Plan Mode 切片①「随时可入」暂不解冻——维持 P32 冻结，触发条件写死

- 日期：2026-09-06
- 决策人：pf-pm；输入源：STATE P32 候选② + s51d 冻结点、research/14（全文）、裁决先例 docs/verdicts/2026-09-05-marketplace-ecosystem.md §3
- 结论：**切片①不做，维持 s51d 冻结点不动**。research/14 归档为 P32 候选②设计输入。解冻触发条件本文 §5 写死（防重谈判）。本文不触发任何代码/包变更，v0.9.10 预览包维持原样。
- 待裁决背景回顾：正方=澄清先行对抓数/多步任务有价值、成本低（模板+入口，s50 通道，桥零改动）、打包+沙盒验证已演练成型；反方=P31「验证优先于扩张」、护航反馈未回、预览包刚冻结再解冻、Plan Mode 属 P32 未到触发条件。

## 1. 问题陈述（谁在什么场景下痛）

主张的痛：妻子发起抓数入库/多步任务时意图不对齐，goose 直接执行导致出卡潮中返工、误触、或做出来的不是她要的。频率假设=每次复杂新任务。

**事实核验（区分事实/假设）**：

| 断言 | 状态 | 依据 |
|---|---|---|
| 妻子已完成真机启动 | 事实 | 2026-09-05 用户确认「可以打开运行」（STATE P31-①） |
| 真实任务链/EDR 行为数据 | **无** | 护航反馈未回（STATE P31-①「任务链/EDR 细节待护航反馈」） |
| 抓数任务出卡 5-15 张、误操作风险 | 假设（机制推演） | s55-56 裁决书预判，非行为数据 |
| 「规划降低返工率」 | **UNVERIFIED** | research/14 §7.4 自认：「靠护航统计验证，不作为承诺写入 P32 裁决」 |
| 弱模型（glm-5.2 级）「计划 or 澄清问题」二分类可靠 | **UNVERIFIED** | research/14 §7.2：无本机证据，模板措辞须沙盒实景实测调 |

不解决的当下代价 = 零已知损失（无一起真实返工发生）；潜在代价 = 若痛点为真，缓解晚到数周。**这是本裁决全部机会成本。**

## 2. 归约（三次为什么）

1. 为什么做切片①？→ 让复杂任务先对齐意图再执行。
2. 为什么意图不对齐是问题？→ 抓数出卡潮中返工与误操作面大（s55-56 推演）。
3. **为什么是现在做？** → 正方答不出独立于「便宜、顺手、机制通了」的理由。便宜改变的是成本曲线，不是价值证据；research/14 证明的是**机制可行**（走 s50 通道、桥零改动），恰恰没证明**该机制有人需要且有效**。

三问回答（本项按提案格式补齐）：

- **用户何时遇到？** 预期在首次真实抓数/多步任务中。该事件尚未发生，触发场景为零观测。
- **不用它怎么死磕？** 直接执行+smart_approve 权限卡兜底（s69 已激活），最坏返工重跑；会话即记忆+工作区版本管理（ADR-0007）使返工可恢复，死磕成本有底。
- **做错的代价？** 入口是可见 UI，「先出计划」按钮 invites clicks。弱模型若产出烂计划/伪澄清循环，零技术用户的 Plan Mode 首次接触即失败体验；信任损伤不可逆，且为调模板要消耗多轮沙盒实景 LLM 调试（含 research/14 §3.3 已知摩擦：write 出卡+60s 超时自动拒，模板须「一次写全」才成立——调参量未知）。

## 3. 张力裁决：验证优先于扩张 vs 团队主动扩张

对照 marketplace-ecosystem §3 先例。该裁决豁免挂起的条件有三，本项**一条不占**：

| 豁免条件 | marketplace（获豁免） | Plan Mode 切片①（不获豁免） |
|---|---|---|
| 用户点名（第一输入源） | 是（主线 2/3 当日点名） | **否**——用户当日四主线已全落地（STATE s69），本项系团队主动扩张 |
| 缺陷级（今天就可能丢数据/出事故） | 是（cpSync 静默覆盖丢原创技能） | **否**——纯增益假设，不解决即零损失 |
| 与未回收的验证解耦 | 是（机制自洽，不依赖真机） | **否**——价值假设与机制可靠性双双 UNVERIFIED，唯一验证载体恰是尚未回收的护航反馈+使用统计 |

「成本低/可重打包/沙盒演练成型」全部承认，但它们只降低**实施**成本，不动摇**价值未验证**这个事实。P31 内测期纪律的存在意义就是管住这一类决策：**机制通了 ≠ 该上车了；有座位的乘客（真实行为信号）出现才发车。** 对零技术用户，「没人点的入口」= 带部署时间戳的浪费，还顺带稀释护航须知（真机简报刚为默认模式变化做过预期管理，不再加需解释的新面）。

## 5. 解冻触发条件（写死，防重谈判）

任一触发即重开裁决（重开时设计起点=§6，不重新归约）：

- **T1 意图错配实锤**：护航反馈中出现「它没问我就做错了 / 做的不是我要的」类反馈 ≥2 次（同任务族内）。
- **T2 卡片疲劳坐实**：单次抓数任务实测权限卡 ≥8 张（s55-56 预判区间 5-15 的中段以上）且发生误触/漏批 ≥1 次。
- **T3 统计信号**：护航 ≥2 周后，s49 使用统计口径下复杂任务完成质量差——多步任务首次成功率 <50%，或同类任务重复发起 ≥3 次。若 s49 现行口径无法直接回答，以护航人工观察记录替代；**不为触发器扩统计代码**。
- **T4 用户点名**：内测用户明确要求「先看计划再执行」类能力（点名=第一输入源，marketplace 先例）。

**反触发清单（以下论据不构成解冻理由，未来不再逐条辩论）**：

1. 「竞品都有了」——对标输入 ≠ 需求，竞品做法在我们的证据序里排最后。
2. 「反正便宜」——成本小不改变价值未验证；最便宜的浪费也是浪费。
3. 「顺手做了/正好重打包」——不解冻已验证冻结面（§4）。
4. 「research/14 写得好」——设计就绪度不是需求证据；它降低的是**未来**解冻的实施风险，不是解冻理由。
