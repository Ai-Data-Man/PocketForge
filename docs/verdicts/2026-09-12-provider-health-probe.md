## 1. 归约与三问

三次为什么：
1. **为什么做探测？** → 配置不动链路也会死（provider 侧静默变更是常态，三周三例），且死了用户不知道、知道了也不会修。妻子唯一发现方式=发一条消息等它石沉大海。
2. **为什么「发了消息会有错误卡」不够、要先于使用？** → 妻子的使用模式是「有事才打开，打开即用」。任何「用了才发现坏」都烧掉一个任务回合；而错误卡对下架形态说的是「等一两分钟再试」——**误导她重复撞墙**。可见性必须先于使用，且归因必须指向真出口（更新模型/换线），不是假安慰。
3. **为什么是「断链告知」不是「断链自愈」？** → 断链成因多样，每一种自动处置都有错误形态：自动换线=turn 失败时工具可能执行一半，重发副作用重复（s50e 正确性裁决）；自动换模型名=选型非机械（v4.1-flash 与其他不等价），悄悄换=输出质量静默漂移；自动关代理=改系统设置越权。且妻子场景有兜底人（护航期是我们），**诊断交给产品、决策留给人**，告警条直达修复入口让兜底人 30 秒闭环。妻子需要的信号形态三要素：**现状（联系不上/模型下线）+ 归因（不是你的错，也不是「等一等」）+ 出口（点这里去修）**。

三问回答：
- **用户何时遇到？** 打开页面准备用或正在用时，provider 侧任何静默变更（下架/换址/全站故障）或本机网络环境变化。护航期内预估 2-4 天一遇。
- **不用它怎么死磕？** 现状=每次断链至少烧一个任务回合；事故一形态 typing 永转真零信号；事故二形态误导性错误卡致重复撞墙；妻子自愈路径为零（她不知道 ⟳ 拉模型是什么）。我们这边=每 2-4 天事后取证一次（s76/s78 两次均如此）。
- **做错的代价？** 被动探测最坏情形=误报一条常驻条+一次多余的面板访问，无破坏面（只读 GET、零自动动作）。越界做自愈才有正确性代价——已裁掉（§4）。

## 2. 做 / 不做 / 推迟的最坏后果

| 选项 | 最坏后果 | 评估 |
|---|---|---|
| **做（最小形态）** | 误报打扰一次；~60 行桥代码+~20 行前端的班车成本；与 s78 在飞服务商工程师的区域冲突风险（排期注记见 §6） | 风险低、可控、有 key-guide/scheduler-drift 两个同量级先例 |
| 不做 | 护航期内再断一次（家族频率支持该预期）：妻子关键时刻对工具失去信任——**「妻子能用」是 P31 护航的核心验证目标，链路可用性是其余一切验证的前提**；我们继续每 2-4 天事后取证 | 不可接受 |
| 推迟到 v0.9.13+ | 同不做，且「下一版再说」没有触发器能叫醒它（backlog 已沉睡 2 天，若无裁决将随护航期漂移）；下一版本目前没有比核心链路可见性更基础的候选 | 拖延无收益 |

**裁决：做，v0.9.12 必做。** 阶段判据：内测护航=验证优先于扩张——本项不扩张任何能力面，只给既有链路补可见性，是护航期最正统的投入。

## 3. 最小形态设计（pf-engineer 可直接领走）

### S1 桥侧探测函数 `probeProviderHealth()`（chat-bridge.tpl.js）
- **探测内容（单次 `GET {host}/models`，Authorization 头，8s 超时——比 test_model 30s 更紧，快速判死快速恢复；超时按 down 报）**：
  - host/model 未配置（无 active 档或 secrets 空）→ **不探**（该态由 key-guide 引导条独占，s51d 语义不变）；
  - 请求失败（ECONN/超时）→ `state:'down'`；
  - HTTP 401/403 → `state:'down', kind:'key'`；其他非 200 → `state:'down'`；
  - 200 且列表**不含当前模型名** → `state:'stale-model'`（事故二形态）；
  - 200 且在列 → `state:'ok'`。
- **同源铁律**：host/model 解析必须与 spawnAcp env 链同源（同一 `activeProvider()` 读法，:600/:610），否则「探 A 用 B」假阳假阴。**实现前先与 s78 服务商工程师合流**：:610 末级回落死名 `deepseek-v4-flash` 若被本批改掉，探测取值随最终链走。
- **附加只读检查（零网络成本）**：注册表 ProxyEnable=1（复用 s64 A1 读法，:1498 区）→ 健康帧附 `proxy:true`。这是事故一形态的诚实覆盖：不装作能探测代理路径，只提示风险存在。
- **缓存与失效**：内存态，零持久化（与 key-guide 同哲学，重启即重探）；TTL 30min；providers save/activate 后缓存立即失效（换档即重探，hotRestart 已有 needRestart 语义 :3502）。
- **全异步**：探测请求不在任何同步路径上（research/09 #7 纪律）。
- **diff 量级**：桥 ~55-65 行。

### S2 三个触发点（无周期心跳定时器）
1. **WS hello（页面打开）**：缓存过期才后台探，未过期直接发缓存态——妻子视角=打开就知道。最坏一天 20 次打开 ≤20 个免费 GET。
2. **turn 失败后**（S26 命中或 reject，:712/:719 既有挂点旁）：防抖 60s 合并安排复检。真实失败是最强探测信号，零额外成本。
3. **桥启动 90s 后**一次（避开冷启资源竞争，兼作护航环境自检基线）。
- **裁掉周期定时器**（6h/24h 心跳）：页面打开触发已覆盖「使用前知道」；无人看屏时探测无消费者。前端维持「无周期轮询」架构现状（research/09 实证清单不得倒退）。
- 健康态变化时向所有活跃 WS 客户端广播 `{sys:'health', state, kind?, proxy?}`（delete 广播 s77 主线5 同款模式）。

### S3 前端告警条（chat.tpl.html，key-guide 克隆）
- 位置/机制同 key-guide（:1775-1795）：聊天区顶部、客观状态判定、零持久化、恢复即消。
- 文案（三态，零术语审读）：
  - `down`：「现在联系不上大模型服务商，发消息可能没回音（不是你的操作问题）。点这里检查线路 →」按钮=打开 ⚙️ 设置-服务商面板（面板内测试按钮/换线均在）；
  - `down+key`：沿用 TURN_KEY_TEXT 口径：「这家服务商的 Key 没配上或不对…」；
  - `stale-model`：「你正在用的模型已被服务商下线，发消息会失败。点这里更新模型 →」按钮同上（面板内 ⟳ 拉取新模型+勾选+保存是既有流程，s78 工程师正在修的区域）；
  - `proxy:true`：附加一行黄色 info「本机开着网络代理，大模型流量会经过它；如果上面的提示反复出现，先关掉代理软件再试」——不阻断、不装作探测结论。
- **不打扰原则**：ok 态零视觉存在；条不弹窗、不发声、不复读闪烁；turn 失败错误卡（第二道网）与条并存但文案互指去重，同因同回合不重复提示。
- 与 key-guide 互斥语义：未配置=不探测、key-guide 独占；配置后健康条接管。
- **diff 量级**：前端 ~20 行。

### S4 验证
- 桩测探针（mock /models server，**不依赖真中转——它会再下架模型**）：down / stale-model / ok / key 四态 + TTL + 换档缓存失效 + 8s 超时路径。
- GUI 实景：布景 stale-model → 打开页面告警条先于任何 prompt 出现 → 面板 ⟳ 拉取换模型保存 → 条消失（零重启端到端闭环=事故二全流程回放）。
- 回归：e2e-chat / fuzz 基线不降线；代码断言=无常驻健康探测 setInterval、探测路径无同步 IO。

## 4. 裁掉项与非目标（与目标同等重要）

| 裁掉 | 理由 |
|---|---|
| **自动换线 / 自动切模型 / 自动重发** | s50e 裁决边界原样有效（401 自动=永久裁掉；半自动准入=护航≥2 周且 upstream≥10 且换线成功率≥50%）。本探测发现的错误**不写入** upstream 计数、不触发任何自动动作——探测是独立只读信号，不冒充用户错误 |
| chat/completions 真实小回合探测 | token 计费成本；/models 列表比对已覆盖实锤的事故二形态。若实录「/models 通但 chat 断」形态 ≥1 次，按 §5 触发器重开 |
| 经代理路径完全复刻探测（事故一精确探测） | node 显式走系统代理=10+ 行协议细节且与 goose reqwest 行为仍难逐位对齐；事故一在目标机是**潜在**风险非实录（实录发生在云开发机）。注册表提示+护航注记（§S1/S3）覆盖；真机实录代理类断链 ≥2 次再重开 |
| 周期心跳定时器（6h/24h） | §S2 已论证：无消费者场景的探测是带时间戳的浪费 |
| Windows 系统通知 / 声音 / 红点 badge | 新打扰面+依赖面，违背零权限便携气质；常驻条已够 |
| 告警条内嵌「一键拉新模型/推荐模型」 | 选型非机械（v4.1-flash 与其他不等价），推荐=替用户挑输出质量；⟳ 流程面板已有 |
| 健康态入使用统计新桶 / 任何持久化 | 不动 stats schema（最小 diff）；turn 失败已自行计数，探测不重复计 |
| 对非活跃档案探测 | 只探 active 档（与 spawnAcp 同源）；换档由缓存失效机制对齐 |

## 5. 升级触发器（写死，防重谈判）

- **T1 代理路径**：真机护航实录代理类断链 ≥2 次且注册表提示未能拦截 → 重开「经代理复刻探测」候选。
- **T2 深探测**：实录「/models 通但 chat/completions 断」≥1 次 → 重开真回合探测候选。
- **T3 一键修复**：stale-model 告警出现后，妻子/护航者经面板修复失败 ≥2 次 → 重开「拉新模型列表+推荐勾选」候选（设计起点=本裁决 §4 裁掉理由，不重新归约）。
- **半自动换线**：仍守 s50e 准入三条件，本探测产出的观测数据可作其输入但不改变门槛。
- 反触发清单（不再逐条辩论）：「竞品有状态页」「反正 test_model 改改就能轮询」「顺手把 /models 缓存给面板用」——先例 plan-mode-thaw §5。
