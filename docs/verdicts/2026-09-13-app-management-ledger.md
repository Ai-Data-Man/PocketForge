## 1. 归约与三问

**「应用」词汇归约（第一问：它在我们产品里到底是什么）**：在本产品现状里，「一个应用」= **一次会话做成的一组产出**——faucet 服务（含表）+ 会话工作区里的制品文件（xlsx 等）。它不是 Replit 式项目容器，也不是需要新建的实体。**裁决：不新建「应用」实体、不建应用注册表状态文件**（ADR-0009 规避 + R2 无天然分组边界不强造分组）；清单以「产出物条目」为实体、以**来源会话为锚**聚合。对妻子的产品文案统一用「它做过的东西」，**禁用「应用/资产/产出物」等术语**（AGENTS.md §5 零术语纪律）。

三次为什么：
1. **为什么用户点名「应用管理」？** → research/25 §1 缺口实录：链路全通（建库建表→数据→xlsx→@引用→面板可见→删除确认）但产出物没有统一清单，三源散在三个面板的三个动词里。用户指令 = 挂起触发器（真机「找不回」≥2 次）的 T4 式命中。
2. **为什么核心是「找回」不是「管理」？** → 妻子场景：「上次那个库存应用再出一版」。她要的是**观察**（找到它在哪）+**指代**（说一句话让 agent 接手），不是治理（改名/归组/权限）。对标收敛（research/27 §A.2）：时间倒序 + 来源回链 + 自动汇集 + agent 自动命名；类型只是检索维度。她的最小形态 = 一页按时间排的清单，每条能点回当时的对话。
3. **为什么现在做最小聚合层而不是全套？** → 三源每源已各自 R2/R4 合规（research/27 §A.3「机制分散但每源已合规」），缺的只是聚合视图（M 级）；护航期规模 <100 条；「验证优先于扩张」——本项不扩张任何能力面，只给既有产出补可见性，是护航期正统投入（provider-health-probe §2 同判据）。

三问回答：
- **用户何时遇到？** 做完一个报表应用后隔几天想续作/复用/核对时。护航期预估每周 1-2 次（使用统计 messages 增长即其前置信号）。
- **不用它怎么死磕？** 现状三条路全是绕路：翻会话列表靠标题回忆（标题是模型自动生成的，质量不稳）；浏览全部是工作区级+搜 id/标题，**搜不到文件名**；⚙️🗄️数据只有表没有文件和时间。妻子自愈路径≈0，实际兜底=问护航的人。
- **做错的代价？** 只读聚合无破坏面（零删除、零写通道、零持久化）。最坏=一个低频 tab 无人看（沉没一个 M 级班车项）；防线=主指标验收句（§6）。

## 2. 做 / 不做 / 推迟的最坏后果

| 选项 | 最坏后果 | 评估 |
|---|---|---|
| **做（最小聚合形态）** | 一个 M 级班车项 + 桥/前端热区排期串行成本 | 三源原料全部现成（§0），无新状态机制；有 research/27 §A.4 已固定的设计起点，设计风险已收敛 |

## 3. 最小形态设计（pf-engineer 可直接领走；设计起点 = research/27 §A.4，不重新归约）

### R1/R3 归属裁决：⚙️ 管理面板新 tab「✨ 做过的东西」

- **R3 论证**：「改了它去哪看效果」——三源全部是**全局资产**（非会话作用域），清单的回答对象是「它给我做过哪些东西」这个全局问题；右栏双 tab（本对话/浏览全部）是会话语境下的消费视图，跨会话资产放进去违反其信息域。⚙️ 面板已是「它有什么」的既安心智域（本事/数据/记忆/定时/插件同族），research/27 §A.5 A1 已固定此归属，本裁决维持。
- **R1 合规**：新 tab = 新信息域 = 一类实体（产出物条目），与现有五 tab 各一类实体同构，不混容器；每视图 ≤1 主清单区块。**规模声明（R2 强制项）：护航期 <100 条**（表 + 成品文件 + 技能三源合计）→ 31-100 档 = 分页（卡片 12/页，pageSlice 复用）+ 搜索；类型 chips 兼作 >100 档升分组（按会话，A.4 预备）的过渡态。tab 数 5→6 为已声明观察点（label 一词区分，无堆叠）。

### S1 建账（hints 文案，0 行代码）——服务级来源的唯一通道

- goose-hints.tpl.md 建库段（:10 区）补一句，句式克隆 forge_table_info 义务（:15 先例）：**建新库完成时，在同库建 forge_meta 表并写一行——description 一句中文人话说清这个库是给谁做什么的、created_at 建库日期、source 填本对话工作区目录名（系统备注里的 data/artifacts/\<这串\>）**。
- 可行性依据（§0 已核）：agent 经 ponytail 注入知道自己的 ws-id；写库用 CLI/HTTP 直连（s78 挂账② MCP stale 的既有 workaround）；R4 同源纪律「机器生成的资产，人话身份是数据管线义务（建时落元数据），UI 只消费不猜」。
- **物化纪律**：模板改动必须重跑 bootstrap（s74 遗留③）。
- **建账方案裁决**（任务书点名评估项）：
  - **方案 A（agent 建账 forge_meta）：采纳。** 成本 S（文案）+ 桥读扩展（并入 S2）；与 IA-3 forge_table_info 同族同哲学；不新建自有状态文件（forge_meta 在 faucet 管理的库内 = 组件自管，ADR-0009 零义务）。
  - 方案 B（桥侧监听/截获）：**否决**——桥不在 agent→faucet 创建路径上（§0）；fs watch = L 级新状态机制 + ADR-0009 全套义务，为回链一个字段不值。
  - 方案 C（无回链降级版）：**作为存量服务的自然降级态保留，不是首版目标态**——「找不回」的直接解药恰是回链（research/27 §A.2 发现 2），砍回链=砍主指标。
  - 存量服务（如 plm）：无 forge_meta = 显示「来源不详」，**不考古不回填**（触发器见 §5-T4）。

### S2 桥端聚合端点 `GET /api/assets`（~100 行，无参数、无持久化、dbOverview 哲学克隆）

- 表源：dbOverview 扩展——每库增读 forge_meta 单行（faucetGet 同轮，缺 = null 降级）；表级 ts 消费 forge_table_info.created_at（读管线已有 desc 同轮，加一列硬化解析）。
- 文件源：ART_DIR 扫描各 ws-* 顶层**成品文件**（扩展名白名单：xlsx/docx/pdf/html/svg/png/jpg/csv；非白名单不出——**替代出路 = 右栏浏览全部/本对话文件树仍在，R2 截断有出路**）+ readWsMap 回链 sid + sessionMeta 标题（管线全部现成，/api/workspaces :2447-2478 同款）。
- 技能源：/api/skills 读法复用。
- 输出 `{ok, items:[{kind:'tbl'|'file'|'skill', name, human, ts, srcSid, srcTitle, ref}]}`；排序 = ts 倒序、null 沉底；物理路径不进主字段（零术语，放展开详情）。

### S3 前端 ⚙️ 新 tab（~150 行，mtabs 注册表 :1389 接入 + 现成模式克隆）

- 每条 = 人话名（表=forge_table_info desc 或「服务.表」结构性事实兜底；文件=文件名；技能=中文名）+ 类型徽章（🗄️/📄/✨）+「来自对话：〈标题〉」+ 时间（无=「—」，**不得编造**）。
- 类型 chips = 筛选非分组（A.4）；搜索框 + pageSlice 12/页。
- 动作两枚：**打开**（文件→既有预览链路；表→切 ⚙️🗄️数据 tab 并展开该表行；技能→技能弹窗——全部既有函数）+ **去当时对话看看**（侧栏 openSession(srcSid) 既有）。删除不在本页（R1 禁同类动作双入口，各域已有）。
- 收录 = 建时自动（数据管线义务）；**禁止 Claude 式手动收藏才进清单**（research/27 §A.1 反面教材）。

### S4 验证

- 静态探针（入 e2e）：端点三源各断言 + 无 forge_meta 降级路径 + 回链解析（ws→sid→title）+ 成品白名单边界。
- GUI 实景（妻子剧本）：真会话建库带 forge_meta → 清单页出现条目带人话名/时间/来源 → 点回链落回原会话 → 该会话说「再出一版」→ agent 按 hints 数据发现纪律（:12）自答库表。
- 回归：e2e-chat / fuzz 基线不降线；物化 cmp 逐位一致 + 仅 pc restart chat-bridge（既有纪律）。
