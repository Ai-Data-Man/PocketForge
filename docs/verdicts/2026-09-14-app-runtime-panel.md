## 1. 归约与三问

**词汇归约（第一问：这次的「应用」到底是什么）**：「应用」= 经 ADR-0003 注册协议落在 apps/<应用名>.yaml、由 pc 拉起的长驻服务（可有网页入口）。它与 s83 已归约的「产出物条目」（表+文件+技能，服务「找回做过的事」）是**两个信息域**：一个是活态运行面（现在开着吗/怎么进），一个是静态历史账（过去做过什么）。s83 把「应用」一词折叠进了后者——用户 09-14 原话证明他要的是前者。**裁决：不改造 ✨做过的东西（s83 红线维持），新建运行面载体**；两 tab 的词汇区分交给命名（§3-R1）。

三次为什么：
1. **为什么用户说「理解错误」？** s83 以「应用管理」立项、交付的是产出物账本——名字承诺了「管理应用」，交付物里却没有 app 运行面（那时 ADR-0003 的 apps/ 模型没进归约视野）。用户搭完 app 后三连问（在哪管理/怎么打开/跑没跑）全部无界面答案。这是**承诺与交付的词汇错位**，不是 s83 交付物本身无用（找回场景它仍成立）。
2. **为什么核心是「观察+入口」不是「治理」？** 零技术妻子对后台服务的全部可用动作 = 看它在不在 + 打开它的页面。启停/日志/编辑是开发者心智；她的补救动作天然是「跟小 forge 说一声」——对话通道本就是产品的万能治理面（agent 有 pc CLI 全权）。给面板加写通道 = 自造竞态和「她停了忘了→又打不开→更困惑」的新问题域。
3. **为什么建账走 agent 义务而不是桥侧推断？** 「怎么打开」的唯一权威知情者是把 app 搭出来的 agent（端口是它选的）。桥侧推断（command 正则挖端口）是猜——猜错给零技术用户的就是一条死链。s83 S1 已确立同款哲学：机器生成资产的人话身份是数据管线义务（建时落元数据），UI 只消费不猜。本裁决把该义务从 forge_meta 表平移到 forge-meta 注释行。

三问回答：
- **用户何时遇到？** 任何一次「帮我做个 XX 应用」会话结束后的任意时刻想用/想确认。频率 = 每次 app 交付后高频回访（app 是长驻服务，不是一次性报表）。
- **不用它怎么死磕？** 现状零出路：不知道端口→打不开；不知道状态→问护航者或重启大法；apps/ 里的 yaml 对妻子完全不可见。自愈路径 = 0。
- **做错的代价？** 只读观察面无破坏通道（零写、零持久化、零监听）；最坏 = tab 无人看（沉没一个 M 级项）。真正的翻车点是 S4 不随批——升级直接删用户 app，比不做更糟，故强制同批。

## 2. 做 / 不做 / 推迟的最坏后果

| 选项 | 最坏后果 | 评估 |
|---|---|---|
| **做（最小观察面 + 建账句 + PROTECTED 随批）** | 一个 M 级班车项；chat-bridge/chat.tpl 热区排期串行成本 | 原料全现成：apps/ 目录、pc list JSON（本机实跑验证）、execFile 先例、s83 建账句式与降级哲学可直接克隆 |
| 不做 | 用户点名二次落空（第一次名字撞车，第二次真缺口仍无面）= 路线裁决失信；app 交付链路「搭完即失联」；升级丢 app 缺陷继续潜伏 | 不可接受 |
| 只修 S4 不做面板（或反之拆批） | S4 单独上 = 保护了用户看不见的东西；面板单独上 = 下次升级面板变空白——**两者互为验收条件，禁止拆批** | 否决拆批 |
| 推迟到护航后 | 同不做，且「app 可交付」是通用数字员工的核心能力面，缺观察面等于该能力不可用 | 拖延无收益 |

**裁决：做，即刻排工程批次（发布窗口归用户，同 s83 主控改判先例）。**

## 3. 最小形态规格（pf-engineer 可直接领走）

### R1/R2/R3/R4 过堂 + 载体裁决：⚙️ 第 7 tab「🚀 小应用」

- **载体 = 管理面板新 tab**，插入位置：✨做过的东西 之后（「它做过的东西→它搭的应用在跑」概念相邻，助发现）。不并 tab、不进右栏（会话作用域消费视图，同 s83 R3 论证）。
- **R1**：一 tab 一信息域一类实体（注册应用条目），与 ledger（产出物条目）分容器；每视图 ≤1 主清单。✨做过的东西**保留不动**（s83 红线：只读、无新实体、无桥侧监听）。
- **命名（R4 前置）**：tab 名「🚀 小应用」——与 小forge 呼叫同族、零术语；用户原话用词即「应用」。**禁用：进程/服务实例/端点/运行时**。tab 内副题一句：「小 forge 给你搭的应用——哪个在跑、怎么打开」。与 ✨做过的东西 的心智区分：**做过的东西=过去的事，小应用=现在开着能用的**。
- **R2 规模声明（强制项）**：终态预期 **<10 个/安装**（长驻服务天然低频新建；0-8 档直接列、无搜索无分页）；触发器 = 超 8 条加搜索（§7 基线规则同款）。
- **R3**：「改了它去哪看效果」——agent 注册 app 后此面板可见，面板即本域归属，无裸露技术配置。
- **R4**：主名 = meta.description（建时落的人话）；缺元数据降级 = 结构性事实（应用名+文件 mtime）+ 占位，**不得编造**；时间无据 =「—」。
- **7 tab 拥挤**：沿用 s83「tab 数为已声明观察点」纪律（5→6→7），不预防性重组；迷路触发器见 §5-T3。
- **空态**（新装必经）：「小 forge 还没给你搭过应用——跟它说『帮我做个 ××』试试」。

### S1 建账（hints 第 5 条 + 模板占位行；0 行桥代码）

- **注释行约定（裁决：注释行，否决 x-forge 块）**。依据 §0：聚合是文本拼接——注释穿透无害；x-forge 顶层键会穿透进 apps.env.yaml 且多应用时**重复顶层键**，赌 pc 解析宽容度 = 拿「一次双击启动成功」验收线冒险，不值。
- **协议补第 5 条**（goose-hints.tpl.md 应用注册协议段，句式对齐 s83 S1 建库留账）：「5. 建账留痕：apps/<应用名>.yaml 首行（processes: 之前）写一行注释 `# forge-meta: {"description":"一句中文人话说清这个应用给谁做什么","url":"有网页入口就填 http://127.0.0.1:端口，没有就删掉这项","created_at":"YYYY-MM-DD","source":"系统备注里工作区目录名 data/artifacts/<这串>"}`——管理面板靠它显示人话名和『打开看看』按钮。」
- **模板补占位**：conf/_app-template.yaml 顶部带 forge-meta 注释占位行（含待填字段），agent 复制即继承、只需填值。
- **物化纪律**：goose-hints.tpl.md 改动必须重跑 bootstrap 物化 + cmp 逐位一致（s74 铁律）；_app-template.yaml 是 conf/ 实文件，无需物化。
- **降级**：无 meta 行 = 降级显示（结构性字段兜底），**存量不考古不回填**（s83 同款；触发器 §5-T6）。

### S2 桥端 `GET /api/apps`（聚合端点，dbOverview 哲学克隆：无参数、无持久化、无写通道；execFile 走 chat-bridge:2151 先例通道）

- **枚举**：fs 读 forge/apps/\*.yaml（目录不存在 = 空数组，不报错）；每文件 YAML 解析（进程集合 = 该文件 processes 键全集，**精确键名匹配，不用前缀猜**——test-app.yaml 的 hello-oneshot 反例证明前缀规则不可靠）+ 首个 `^#\s*forge-meta:\s*(\{.+\})$` 注释行 JSON 解析（坏 JSON = 当无 meta，不炸端点）。
- **状态合并**：execFile(pc.exe, ['-p', pc.port, 'process', 'list', '-o', 'json']) 一次取全量，按进程名精确对账。人话映射（用布尔/数值字段，**不依赖 status 字符串词汇**）：is_running=true → `run`；is_running=false 且 exit_code=0 → `stop`；is_running=false 且 exit_code≠0 → `fail`；yaml 有而 pc 列表无 → `absent`（下次开机自动带起——结构性事实：pc up 每启聚合拉起）。
- **URL 三层**：① meta.url（agent 建账，最高优先）；② readiness_probe.http_get（host/port/scheme/path 合成，agent 亲配的 HTTP 入口=最强结构性信号）；③ 都无 → null。**command 字符串端口正则：裁掉**（§4 表）。
- **listenPorts**：`process ports <name>` 逐 app 进程取实听端口并集（每请求至多 N 次子进程调用，N<10 规模下可承受；失败 = 空数组静默）——**仅入展开详情，不作「打开看看」来源**。
- **输出形状**：
```json
{ "ok": true,
  "apps": [{
    "id": "<yaml 文件名去扩展名>",
    "human": "<meta.description 首句 | null>",
    "url": "<meta.url 或 probe 合成 | null>",
    "createdAt": "<meta.created_at | 文件 mtime ISO | null>",
    "srcSid": "<meta.source→workspace-map 解析 | null>",
    "srcTitle": "<sid→会话标题 | null>",
    "procs": [{ "name": "myapp-web", "state": "run|stop|fail|absent", "exitCode": 0 }],
    "state": "run|stop|fail",
    "listenPorts": [8199]
  }] }
```
- **排序**：state（run 在前）→ createdAt 倒序、null 沉底。app 级 state = 任一 fail → fail；全部 run → run；否则 stop。**yaml 物理路径不进主字段**（零术语，放展开详情，s83 同款）。

### S3 前端 ⚙️ 新 tab（mtabs 注册表接入，现成模式克隆）

- **卡片元素**：状态徽章（✅运行中/⏹已停/⚠️出错）｜主名（human 或降级「〈id〉·小 forge 搭的应用」）｜注册时间（无=「—」）｜进程行（名+状态；单进程合并进卡片头）｜展开详情（监听端口、来源对话回链「来自对话：〈标题〉」（有则可点，openSession 既有）、yaml 位置收进折叠技术区）。
- **动作仅一枚**：「打开看看」（url 非空时，window.open）；url=null 显示人话句「这个应用没有网页，它在后台做事」——**不猜、不放死链**。
- **出错态行动指引**（无按钮）：「⚠️ 出错了——跟小 forge 说一声，让它看看怎么回事」（补救=对话通道）。
- **刷新**：tab 打开拉一次 + 卡片区右上「刷新看看」按钮。**无轮询无推送无 SSE**（0-8 条规模下实时性无消费者；桥侧持续监听成本结论沿用 s83 精神）。

### S4 升级保护（PROTECTED += 'apps/'，与功能同批，禁止拆批）

- 依据 §0：现状保护 conf/apps.env.yaml 是死字（每启重聚合），不保护 apps/ = **每次升级删光用户已注册 app**——面板做完第一个升级就变空，功能与保护互为验收条件。
- 改法一行：PROTECTED 数组追加 `'apps/'`（isProtected:72 前缀匹配已支持，无需改函数）。
- 连带核对（工程侧）：升级包**不含** apps/ 目录（出厂零 app，目录由首次注册自然产生）——避免差量把空目录判成删除源。

### S5 验收（含 §8 测试纪律）

1. **活体主路径**：真会话自然语言让 agent 建 app（无额外提示）→ yaml 首行带完整 forge-meta → 热注册 → 面板 🚀 出现该应用 ✅ + 「打开看看」落到真实页面。
2. **降级路径**：剥掉 meta 注释行 → 应用仍列出（结构性兜底字段，无编造文案）；有 http_get probe 无 meta → 「打开看看」仍可用（第 2 层）。
3. **诚实降级**：无 url 无 http_get → 「没有网页，它在后台做事」，无按钮无死链。
4. **§8.1 冷启路径**：解压安装的包上注册 app → 整机重启/重启启动器 → pc up 自动带回 → 面板恢复 ✅（禁 dev 树冒充）。
5. **§8.2 升级路径**：旧版本包装已注册 app → 按发布说明升级 → apps/\*.yaml 存留 + 面板恢复（S4 的直接验收）。
6. **探针**（入 e2e 静态）：端点断言（枚举/join/状态映射/坏 meta 降级/absent 态）；dev 树两个测试残留 app 转为探针 fixtures，用后自清（s82 探针自清纪律）。
7. **回归**：e2e-chat / fuzz 基线不降线；hints 物化 cmp 逐位一致；e2e/fuzz 不并行。

## 4. 裁掉项与非目标（与目标同等重要；防扩张清单进审查依据）

| 裁掉 | 理由 |
|---|---|
| **启动/停止/重启按钮** | 写通道+竞态；她停了忘了 = 自造「打不开」新困惑；治理已走对话通道（agent 有 pc CLI 全权，说一句即启停）；s83「观察>治理」同判。触发器 §5-T1 |
| **command 字符串端口正则兜底 URL** | 推断可错（非监听数字/pg 类端口）；错 URL 对零技术用户 = 死路无自愈；R4 不猜。触发器 §5-T2 |
| **process ports 实听端口当「打开看看」来源** | 实听 ≠ 网页入口（pg 5432 反例，§0 实证同族）；只配进展开详情 |
| **日志查看** | 开发者心智，妻子看不懂；排障责任人 = agent（对话带上下文）；「无消费者场景 = 浪费」 |
| **faucet/基础设施进程混入本 tab** | 🗄️数据已覆盖 faucet 域——混入即重复，**用户本次抱怨的正是重复**；基础设施键 ADR-0003 本禁 agent 定义 |
| **app yaml 编辑/删除/改名 UI** | 写通道越权（agent 域文件）；删 app = 跟小 forge 说（对话即治理）；R1 禁同类动作双入口 |

## 5. 升级触发器（写死，防重谈判）

- **T1 启停按钮**：真机实录用户想手动启停某 app ≥2 次 → 重开（设计起点 = 对话通道对照下的差距分析）。
- **T2 URL 兜底增强**：真机实录「面板说没有网页入口但该 app 实际有网页」≥2 次 → 开 command 正则兜底（先做命中误报审计再上）。
- **T3 tab 拥挤/迷路**：7 tab 间找错 ≥2 次 → 重开 IA 分组评估（设置类/资产类分组条，不做预防性重组）。
- **T4 规模升档**：apps >8 条 → 加搜索（§7 基线规则）。
- **T5 ledger/运行面混淆**：真机实录用户在 ✨做过的东西里找运行状态 ≥2 次（或重复感抱怨再现）→ 重开两 tab 边界（含 ledger 表源瘦身候选）。
- **T6 存量回填**：护航者手动为老 app 补 forge-meta 实录 ≥1 次 → 评估一次性回填。
- 反触发清单（不再逐条辩论）：「竞品有进程管理器/日志终端/资源仪表盘」「加自动健康巡检」——plan-mode-thaw §5 先例。
