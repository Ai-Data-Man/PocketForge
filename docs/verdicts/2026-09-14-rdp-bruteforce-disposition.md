# 2026-09-14 云主机爆破事件处置（三地 IP 定位 + 显式阻断）

## 1. 事件

外网对云主机（`LAVM-138S0Y6V2O`，公网 `172.16.0.8` 内网侧映射）发起 RDP/WinRM 暴力破解：

| 指标 | 值 |
|---|---|
| 入口 | TCP 3389（RDP）、5985（WinRM）；135/445/137/138/139 同暴露 |
| 失败登录（4625） | 24h 内 17,496 条（type3 NTLM 17,434 / type2 62） |
| 速率 | ≈14 次/分（21:00-15:00 持续） |
| RDP 接受连接（RdpCoreTS 131） | 单 2 分钟窗口 >30 条，来源 IP 高度轮转 |
| 攻击目标 | `Administrator` 为主 |
| 成功入侵 | **无**（4624 成功登录仅来自用户自有 IP，无攻击源 IP 成功记录） |

初始处置曾把 RDP/WinRM 放行规则来源收敛到用户当时确认的两个 IP（武汉办公 `27.17.163.229`？→ 实为 `27.27.163.229`、襄阳家 `27.17.34.18`），但**爆破未停**——因为系统中存在多条 `Port=Any` + `RemoteAddress=Any` 的系统级放行规则（Windows Search、你的帐户、工作或学校帐户、开始、桌面应用 Web 查看器、Windows 安全中心、sing-tun 等），它们绕过了端口级收敛。

## 3. 处置（显式阻断，优先级高于放行）

Windows 防火墙语义：**Block 优先于 Allow**；无匹配 Allow 时入站默认阻断。因此不改动/不删除任何系统规则，只追加两条高优先级阻断规则，把非放行网段全部封死。

放行空间（三地）：

```
武汉·公司   27.17.34.0/24
武汉·出租屋 171.83.0.0/16        （5G 动态池，需整段）
襄阳·家     27.27.160.0/20       （含 162~176 轮转余量）
```

阻断集（= 全 IPv4 减去放行空间减去私网，私网/环回故意不封以保留云 VPC 内管理通道）：

```
0.0.0.0-9.255.255.255
11.0.0.0-27.17.33.255
27.17.35.0-27.27.159.255
27.27.176.0-171.82.255.255
171.84.0.0-172.15.255.255
172.32.0.0-192.167.255.255
192.169.0.0-255.255.255.255
```

规则：

```
PF-SEC-BLOCK-IN-TCP   inbound block  TCP  135,139,445,3389,5985,47001
PF-SEC-BLOCK-IN-UDP   inbound block  UDP  137,138,3389
Profile=Any
```

同时对既有 3389/5985 放行规则（按端口匹配，避免本地化显示名问题）执行 `Set-NetFirewallRule -RemoteAddress` 收敛至三地空间：
`{063C8AF5-...}`、`{510734C4-...}`、`{0B23514C-...}`（远程桌面，含 Port Any 变体）、`WINRM-HTTP-In-TCP`；Public 变体（`WINRM-HTTP-In-TCP-PUBLIC`、`{C20250E4-...}`）保持 `LocalSubnet` 不动。

## 4. 验证

- 阻断规则下发前基线：`4625 last5min=29`（≈14 次/分持续）；活动攻击者 TCP 连接 4 条（`45.227.254.153` ×3、用户会话 ×1）
- 下发后即时：`4625 last1min=1`；攻击者三条连接被立即清除，仅剩 `172.16.0.8:3389 ↔ 27.17.34.18:41087 ESTABLISHED`（用户当前 RDP 会话**不受影响**，未断线）
- 5 次滚动采样（每次间隔 45s，窗口 3 分钟）：

```
4625_3min=0  newest=-  distinct=0 | 131_3min=0 | ESTsrc=27.17.34.18:41087   ×5
```

判据全部满足：最近 3 分钟 4625 = 0（旧攻击在 15:02 前已停）、RdpCoreTS 131 接受事件 = 0、用户来源会话保持。
- **静默时长核验（15:11）**：末条 4625 = 15:02:23、末条 RdpCoreTS 131 = 15:02:22 —— 规则下发后**静默 9.1 分钟零攻击**（此前为 ≈14 次/分持续）。
- 本机回环服务不受影响（防火墙不过滤 loopback）：stack 端口 8790/8099/8092/5432/4222 TCP 连接全部正常，`/healthz` 8790=200、8092=200。

## 5. 回滚

```powershell
Remove-NetFirewallRule -DisplayName 'PF-SEC-BLOCK-IN-TCP','PF-SEC-BLOCK-IN-UDP'
```

放行规则的来源收敛如需回滚（恢复到 `Any`）：对本机 `远程桌面*` 与 `Windows 远程管理(HTTP-In)` 规则执行
`Set-NetFirewallRule -RemoteAddress Any`。

## 6. 遗留与建议（需用户在云控制台侧完成，本机无法替代）

1. **云安全组是权威闸门**：本机防火墙只兜住主机层；若云控制台安全组对 3389/5985 放开 `0.0.0.0/0`，则爆破包仍会打到主机（被丢弃，但日志与资源仍被消耗）。建议在云控制台把 3389/5985 来源改为三地网段白名单。
2. **残余 `Port=Any + Remote=Any` 系统放行规则** 仍存在（Windows Search、你的帐户、工作或学校帐户、开始、桌面应用 Web 查看器、Windows 安全中心、sing-tun/TaishanNet2、AllJoyn、核心网络 IPv6/IGMP 等）。这些规则在 Domain/Private 配置下生效；当前网卡为 **Public** 配置文件，Port 级阻断规则已覆盖 3389/5985/445/135，故实际暴露面已收敛。若要彻底最小化，需逐条评估这些系统组件的真实需求（不建议盲删）。
3. **非标准端口服务**仍在 `0.0.0.0` 监听：`8124`、`8199`、`8787`、`9119`、`19527/19528`、`20128`。其中 hermes / 9router / e2e-report 等属于开发测试用，建议改为绑定 `127.0.0.1` 或加防火墙白名单。
4. **账户策略**：确认 `Administrator` 是否可改名/禁用（默认管理员名是爆破首选目标）；启用账户锁定策略（例如 10 次失败锁 10 分钟）可显著降低在线爆破效率。当前日志显示 24h 内 17,496 次失败却无锁定，说明策略未启用。
5. **RDP 加固**：建议启用 NLA（网络级身份验证）要求，并考虑在云控制台前置跳板/VPN。
