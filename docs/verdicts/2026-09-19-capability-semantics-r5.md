## 1. 归约与三问：为什么治理两轮后用户仍判「根本没有治理」

**词汇归约**：用户三轮原话的递进——第一轮「有重叠，用合适的产品概念重组」，第二轮「根本没区分出任何语义差别」，第三轮（改向）「机制三分类反而比当前概念好，做成一个反而奇怪」。合起来是一句话：**分类骨架是对的，骨架上的语义层从来没建过。** s95 划了三家（治容器归属）、r4 治了屋内重复（同实体同信息只渲染一处），两轮的共同盲区：三个容器词「本事/技能/插件」在自然汉语里是「它会的事」的三个近义词，没有一个承载机制差；条目描述各自为政，近义能力跨类并存时互不指路。用户看到的是三张清单里躺着三堆「它会的事」——**从内容反推分类，分类当然显得任意**。本轮 unify 提案被否，证明答案也不是消灭分类，而是让分类第一次被说出来。

三次为什么：
1. **为什么机制差异用户感知不到？谁的责任？** 机制差异真实存在且用户可感——器官出厂不可增删、工具装了多个外部进程、做法改变的是行为不是配置——但产品从未把它翻译成用户语言：词不承载（三个近义词）、母句缺失（三个容器没有一句定义）、描述不划界（近义对互不指路）。感知不到不是用户的局限，是概念层的欠账。
2. **为什么修词不修结构？** 结构已被两轮治理验证为正确且低成本稳定（7 tab/弹窗/端点全部合理运转，探针锚密布）；本轮病灶全在概念层（词/定义/描述/生命周期），结构手术=用大 diff 治小病+翻两轮已验证的案。熵减：换词、补母句、修描述、加一个可逆操作，结构零动。
3. **为什么手艺要按 100+ 立项而不是等实录？** 增长引擎四信号三个是 agent 自判（F9），增长不经过用户决定，实录触发器等不到用户点头的样本——只会等到问题本身；且成本端不在 UI（F12 已合规）在每回合常驻上下文（F6①），规模越大每回合都在付费。预测性立项的门槛=机制必然性（协议自触发）×成本恒常性（每请求在场），两条都满足。

三问回答：
- **用户何时遇到？** 每次打开三个能力面板试图回答「它会不会X/X在哪」时（心智建模失败）；手艺过 30 条后每次对话（上下文常驻成本，隐性）；想「先别用这条但别删」时（零出路，只能删）。
- **不用它怎么死磕？** 靠试探和问人；近义能力三处乱试；过期做法删了心疼、留着碍事。
- **做错的代价？** 本批以换词/补句/修描述为主，无破坏面；最大风险=换词引发探针锚漂移（F14）与物化复活（V2）——分别由锚清单（§6）与验证前置（§6-V2）兜住。

## 2. 主线①：三类语义身份重造（概念层立法）

### 2.1 类身份定义（每类必须三问可答）

| 维度 | 🧠 **自带的**（goose 内置扩展） | 🔌 **工具**（MCP） | 🧩 **手艺**（skills） |
|---|---|---|---|
| 机制本质 | 出厂长在它身上的器官 | 后来添置的外接工具服务（装一个多一个外部工具进程） | 教它干活的做法册（提示词型） |
| **从哪来** | 出厂自带，不可增 | 从工具目录装（npm 后台装） | 出厂带的 / 从市场装 / 它干活时自己学会 |
| **怎么变** | 只能开/关 | 装 / 开关 / 卸 | 装 / 学 / 卸 + **停/启（本裁决新增，§5）** |
| **变了什么** | 它「有什么」（身体部件） | 它「有什么工具」（外接设备） | 它「怎么干」（方法），不动它的身体和工具 |
| 操作的诚实呈现 | 无「删」钮（出厂不可拆） | 全套：装/开/关/卸 | 开/关/删按条目呈现；出厂与装的条目同权 |

三身份的判别句（写入 R1 执行口径，§10）：**同一个能力可以以三种形态并存（有浏览器=器官；添了抓取器=工具；学会「表格入库全流程」=手艺），并存的合法性=两侧描述双向划界**（什么时候用这边/什么时候用那边）；不可解释的并存才是归置缺陷。

### 2.2 三个容器词与母句（S1 交付物，妻子面零术语）

- **tab「🧠 本事」→「🧠 自带的」**；h3「自带的（出厂长在它身上）」；fnote 母句：「这些是它出厂就长在身上的：数据库、浏览器、长期记忆。只能开和关——关上哪个，它这次就不用哪个（重启数字员工后生效）。添不了新的，也拆不掉。想给它添工具，去「🔌 工具」；想看它学会的做法，去「🧩 手艺」。」
- **tab「🔌 插件」→「🔌 工具」**；h3「工具（后来添的外接家伙）」；fnote 母句：「这里是从工具目录给它添的外接工具。跟出厂自带的不一样：这些是后来装的，装一个多一件家伙，不用了可以卸掉。带「官方」牌的是官方出品，其余是自己加的。装、卸、开和关都在这里（重启数字员工后生效）。」
- **弹窗 title「🧩 小 forge 的技能（它学会的本领）」→「🧩 小 forge 的手艺（它学会的做法）」**；弹窗 tab「我的技能」→「它的手艺」、「＋ 添加新技能」→「＋ 去市场学新做法」；fnote 母句（S1 版，S3 落地后追加尾句见 §5.4）：「这些是教它怎么干活的做法册：有出厂带的，有从市场装的，还有它干活时自己学会的。工具说的是「它有什么」，做法说的是「它怎么干」——聊天里说到相关的活儿它会自己用；也可以点「让它现在用」。」

选词记录（防重谈判）：「手艺」胜出因它唯一自带「习得」语义且零术语；被否候选：做法（作句中名词用，作容器词太平）、本领（与旧文案撞车且同为泛称）、技能（被用户点名淘汰）。**「 unify/统一能力中心」为反触发，用户已拍死，不再评估。**

### 2.3 R1 规范的重新解读（不改 R1 条文，补执行口径）

R1「一个容器一类实体」维持且被本裁决加固：三类=三个机制类，各自容器单一实体。新增执行口径（§10 给 AGENTS.md §7 修订文本）：**每个实体容器必须载一句母句定义（从哪来/怎么变/变了什么可答）；条目归置必须可被类定义解释；跨类近义并存必须双侧描述划界。** 类的形态差异（器官型/外部进程型/提示词型）对妻子不暴露——由母句和操作集承载，不另设「形态」字段。

## 5. 主线③：手艺 100+ 增长引擎与生命周期（S3 交付）

### 5.1 成本结构（为什么 UI 合规不是答案）

每条手艺的 名字+描述 一行**每次推理请求常驻**（F6①）；正文按需（load_skill）不占常驻。100 条×描述均值≈5-10K tokens/回合，外加选择精度退化（协议自认漏触发风险随条目数上升）。**结论：手艺的规模成本在上下文不在 DOM——唯一用户侧杠杆=控制「常驻条目数」，即停/启。**

### 5.2 生命周期补全：停/启（s95-D3 触发器兑现，改判为预测性立项）

- **状态机**：在用 ⇄ 停着；卸（删档）维持第三操作。**停=不进上下文、不触发、档案留在盘上**（学习成果不删）；启=一次改名还原。出厂/装的/自己学的条目同权可停。
- **机制**：SKILL.md ↔ SKILL.md.off 同目录改名。goose 与桥双盲（两侧均精确匹配 SKILL.md 文件名，源码级已证 F10）；零 goose 改动、零 fork、单 rename 事务可逆。**与 v150 桩是两种深度互不替代**：桩=常驻一行反指令（对抗二进制内置必需）；停用=完全出上下文（用户自备手艺专用）。
- **生效时机**：V4 验证 prompt_parts 每请求评估——若证实则停/启**下回合即生效免重启**（比工具的重启语义更好用，文案如实写）；若否，随批写「重启后生效」。
- **桥改动**：/api/skillstore POST 新增 op:'disable'/'enable'（改名+失败回滚；未知名 400；.off 状态重复 disable 幂等 ok；.md+.off 并存按 .md 为真并报错收敛）；scanInstalledSkills 双扫（.md+.off）输出 active 字段——/api/skills 响应 +1 字段，余形状不变。
- **台账接口**：停着的 self 手艺仍在台账在册（台账=做过的事的记录，不减；openAsset 定位照达，行内状态可见）。s94 收录判据零触碰。

### 5.3 批量与找回（R4 三支柱继承 + slash 补课）

- **批量停/启（新开）**：复用 r4 整理模式组件（勾选/全选当前过滤结果/动作条），单确认、可逆低危——r4 §2.2 裁掉「技能批量」的理由（误删不可逆）对「停」不成立，r4-T2 门控范围相应收窄为**批量卸载**仍守触发器。R4 三支柱（页大小/批量/分页）在统一口径下继承：手艺清单页大小可调已落（F11），本批补批量档。
- **状态 chips**：「全部 / 在用 / 停着」（made-chips 同款）；与来源 chips 并列。100+ 条停用混排时的找回主维度。
- **slash 溢出提示（r4-S3b 同门补课）**：命中 >14 时补「还有 N 个，多打几个字缩小范围」；装/卸/停启后 loadSkillCmds 重拉（V5 确认刷新钩子）。
- **不建**：服务端分页/虚拟滚动维持不做（r3 §5-1）；12/页默认不动（可调已落，9 页痛点=档位一键事）。

### 5.4 上下文诚实注（S3 落地后弹窗母句追加尾句）

「它每回干活前，会把开着的手艺都过一遍；关掉的手艺它不翻、也不占它的心思。」——零术语、无数字、把停用的价值说穿。不做上下文计量表（数字=术语化，非目标 §7-4）。

## 7. 红线与非目标（与目标同等重要）

**红线（不许动）**：
1. **机制三分类与三容器结构不动**（用户拍死）：7 tab 数量与归属、🧩 弹窗独立性、三端点（/api/extensions、/api/mcpstore、/api/skills）形状（+active 字段除外）全部维持；**不做统一能力中心/不合并商店/不建统一实体**——反触发，不再评估。
2. **台账零操作红线**（s94/s81）：只读、收录判据不变；S1 只改指路词汇。
3. **零 goose 改动/零 fork**：停用走文件系统语义；桩机制维持。
4. **零术语**：新词集（自带的/工具/手艺/做法）与全部新文案过 R4；MCP/pkg/npm/技能 只在折叠技术区与代码。
5. **R4 三支柱继承**：页大小可调/分页机制不动；批量=可逆档（停/启）本批开、不可逆档（卸）仍门控。
6. **热区纪律**：chat.tpl/chat-bridge 单工程师串行批；模板改后 bootstrap 物化 cmp 逐位一致。

**非目标**：
1. **🗄️ 数据面板规模化不在本裁决**：用户同期批评④（一个应用很多表）真实成立，主控已核事实（dbOverview 硬截 200 表+每表一次行数请求风暴+截断后搜索盲区）——工程修复批另行在飞，本裁决零触碰 mpane-db/dbPaint/dbOverview 及其护栏值；边界声明防漏：数据域的膨胀治理进度以该批裁决为准。
2. 不做上下文计量表/预算数字/自动退休/语义去重合并（学习成果不被机器静默处置；T2 触发器另挂）。
3. 不做批量卸载（r4-T2 门控维持）、不做服务端分页/虚拟滚动（r3 维持）。
4. 不动 mem/sched/apps 容器（仅受 S1 指路文案波及）；桩维持不可见。
5. 不改 agent 面协议文件措辞（skill-sediment 等是 agent 面，妻子不见；换词只换妻子面）。
