## 1. 复盘（主控认账的两个错误）

1. **把 s98 单线实证当普适约束**：「参数通道死透」是 research/35/37 在 9router×glm 线上的实测，被我当成了"思考深度只能换模型"的物理定律，进而把机制内部（家族别名路由）翻译成用户配置项——ZCode 证明正确抽象是**同模型档位集（values）+ 翻译层（map）**，模型路由最多是翻译层的私有实现。
2. **没有源码级研究就拍设计**：裁决书基于两张截图转述+s98 机制约束直接归约，用户一句话推翻（挖掘自查的"一句话推翻测试"写了却没通过）。教训固化见 AGENTS.md §9。

## 2. 设计定稿（ZCode 骨架 × PocketForge 消费面 × 妻子人话）

### 2.1 能力配置=独立弹窗（废 inline 展开）

模型池行「配置」按钮（原「能力」更名）→ **弹出「编辑模型配置」弹窗**（对齐 ZCode 图1 形态）：独立 modal 遮罩，✕/Esc/点遮罩关闭，关闭不关主设置弹窗。字段：

| 字段 | 形态 | 依据 |
|---|---|---|
| 能不能看图 | select 能看图/不能看图 + 注「贴照片时用得上」 | 消费面=展示+上传预期（s99 维持） |
| 上下文大约多少字 | 数字信息行 + 「（估计）」标注 / 留空按估计 | ZCode contextWindow 同位；信息行非旋钮 |
| **思考档位（从低到高）** | **有序档位集，标签按钮可增删**（如 低/深/尽全力，值域=该模型真实支持的档）+ 自动识别标注 | ZCode `reasoningLevelsOrdered` 同构；goose configOptions 真消费面 |
| （技术折叠，只读） | 一句人话：「这些档位实际怎么传给服务商——按各家接口规范自动翻译，不用您管」 | 展示翻译体系存在感，非假旋钮 |

**「快慢怎么调」三选与「给它配一个深档：深档用哪个模型」整体删除**——负验证：ZCode 全库 0 处换模型形态（research/38 §2）；思考深度=同模型档位，模型配对（X-flash↔X 家族）是桥 llmproxy 的私有实现，**用户面零出现**。

### 2.2 模型池形态（三条新批评）

- **池头行**：搜索框（过滤模型名，空态「没有匹配的模型」）+「＋添加模型」按钮（点击池头就地出输入行；从池尾 addrow 迁移）。
- 池行维持：勾选（=启用，单一真相源）+ 模型名 + 「（猜的）」来源标注 + 「配置」按钮。
- **R2 存量声明翻案**：AGENTS §7「model-pool=勾选选择面（声明+触发器 T5）」中"无搜索"条款被用户点名废除——勾选选择面同样补搜索（机制内建：池≤8 直列时搜索框仍在场但 pages≤1 隐藏翻页器的既有先例同款——**搜索框恒在场**，R2 出生即建）。

### 2.3 数据面（caps）：variant 桥自管化，schema 升版

- `data/model-caps.json` `_schema:1→2`，同提交注册 STATE_SCHEMAS steps 迁移（ADR-0009）：
  - `thinking.variant` 字段**保留读路径**（桥家族注册表/gradient 生成照旧消费），但标记为 **bridge-managed**：`validModelCapsPatch` **拒收 user patch 携带的 thinking.variant 变更**（人话拒因：家族配对由系统自动管理）。
  - 启发式识别器照旧自动写 variant（桥自管字段）；`user:true` 只跟用户真改过的字段（看图/上下文/档位）走。
  - 档位语义统一：`thinking.levels` 为档位集真相源（有序）；`mode` 字段保留兼容读（迁移：none→levels 保留空语义、native→五档预设、variant→沿用现 levels）——迁移自测随批。
- **机制红线零动**：llmproxy/别名/gradient 生成/零重启家族切换/spawn env——全部桥内既有逻辑零改（本批只动校验门与呈现）。

## 3. 非目标与边界

- 顶栏 #think 挡位选择（家族两档/五档/禁用/隐藏四态）**不动**。
- 不合并 ⚙️🧠；左导航（s99 §2 设计A）不动。
- 智能配置：本地等价物=启发式预填+「（猜的）」标注已存在，**不引入云端推荐**（无此基础设施，触发器=真机用户误识别率实录≥2 次再议）。

## 5. 挖掘自查（本轮必过）

- **一句话推翻**：「为什么档位还要用户配？」——启发式必错（同 s99 论证），档位集是该模型真实支持面的声明，错了顶栏五档会对不上 goose 实际放出的档（真消费面）；「为什么留技术折叠句？」——展示翻译体系防止未来再次被误认为"没有映射"；它不可改所以不是假旋钮。
- **机制没入口**：家族配对从此**没有用户入口**（这正是批评的修复），桥自管+探针钉死。
- **大件只用一次**：弹窗=每模型配置一次的低频面，与 ZCode 同频；池头搜索在池小时空态无害恒在场。
- **LLM 体感**：顶栏挡位是妻子唯一的深度入口，位置与文案已验证（iat20b），本批不动它。
- **时间底线**：T1+T2 单工程师半-一天，T3 半天。

## 修订（2026-09-22 主控，QA s100 P2 触发）：§2.1「思考档位可增删」降级为只读信息行

QA 实证 caps.thinking.levels **零消费方**（顶栏值域=家族硬编码两档/goose 回包/隐藏三源，编辑器档位改动对顶栏零联动）——本裁决 §2.1 的"可增删"字段违反了自身援引的 s99 §3.1 消费面判据（一句话推翻测试未过门，AGENTS §9 第 3 条自罚）。修正（71a0318）：
- 档位字段=只读信息行「顶栏快慢」三态（家族→「快一点/想深点——系统按模型自动配对的」+逃生口副句「想解除配对：把其中一个模型从可选池勾掉」；native→「跟模型自带档走，开对话见顶栏」；无→「顶栏没有快慢选择」），如实呈现顶栏真实状态。
- 保存 patch 收窄 {multimodal, context_len}；thinking.mode/levels 用户写通道全关（P3-a 同批封堵）；启发式新写 variant 补五档与迁移同口径（P3-b）。
- **档位集用户可调的重新立项触发器**：llmproxy 五档透传进家族顶栏（机制上已支持五档→两模型翻译，现仅 UI 简化为两档）且真机实录到用户要中间档 ≥1 次，或对齐 ZCode 开发者面时。
- 留档 P3：levels 纯 API 写通道仍开（无消费方=写入孤儿，无用户面伤害）；levels 有序/值域门未强制（无用户写方=暂无入口）。
