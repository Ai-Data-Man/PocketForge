**裁决理由**：台账观察项实录歧义（可读成「以后别做这件事」，实义「这类不再问=默认拒绝并记住」），且指明缺口=「sub 行只解释了允许侧」——副行解释是权限卡既有模式，补半句是最小 diff，语义/按钮行为零变化。**边界：本批只动 sub 行，不动四按钮字面、不动任何权限语义**；工程中若发现必须动按钮布局/行为才能消除歧义 → 停手回主控（那属交互设计，§9 前置）。按钮字面是否重措辞，缓办等使用证据。

**验收判据要点**：sub 行同时覆盖允许侧与拒绝侧（「允许的以后直接做，拒绝的以后直接跳过不再问」方向）；DECLINE_RE（dbccb03）解析的是模型侧文本，与按钮/副行文案无耦合，不得误伤；permcard 相关探针断言随迁红绿对照。

### 3.1 R4-F3 确认瀑布一键升格「这类都允许」【权限语义，默认保守】

**缓办理由**：smart_approve 默认模式点多是安全设计的代价，s69 用户主线裁决域；R1 刚治好「超时指责用户」，护栏已完整（💡 提示卡 + 单卡级「以后都允许」 + 切自动干活三条出路在场）。无用户信号前扩大允许面=拿信任换便利，方向反了。

### 3.2 刷新不恢复当前会话

**缓办理由**：妻子视角可辩护（侧栏第一条就在，R2 观察项原判「可接受」）；当前零抱怨信号；会话指针生命周期域 R5 刚修过竞态，盲动风险大于收益。属新交互设计，§9 前置。

### 3.3 窄窗 ≤400px 无响应式

**缓办理由**：320px 单字竖排是真缺陷（R2-P5 实证）但触发场景频率未知——妻子把窗口拖到 ≤400px 的真实发生率无任何证据；1280 基线恒定 300px 不可见溢出同族留档。无使用证据前投中等 CSS 工作量=为未见过的场景付费。
**触发器**：真实窄窗使用证据（用户反馈/使用统计）或 UX 打磨专项批；届时先定响应式断点设计方案（§9 前置）再动工。
