# S107 裁决：报表 happy path 权限卡墙 → 挂只读 read 工具（缺陷 #2，P2）

裁决 pf-pm 2026-10-02。证据：docs/research/2026-10-02-s107-read-tool-permission.md（VERIFIED-RUN 三证：源码+生产转储+沙盒四臂）+ tmp/s107-roundA-findings.md #2/D2（单报表任务 7 卡 6 超时：todo/shell type/shell dir/edit）。

## 裁决：修，选 A，附两条一行级配套

**A = 经既有 vendored stdio MCP 通道挂一把 `read_only_hint=true` 注解的工具，名 `read`，读 data/artifacts/ 下文本文件返回内容。** smart_approve 判定链第②步确定性放行（inspector :172-176）：零卡、零 judge 开销、只读、不碰任何 write 类授权。

配套（同批，各一行）：
1. `.goosehints` 加一行：读工作区文件内容用 read 工具，不要用 shell type/cat 读文件——**须知.md 也同族受益**（系统每任务提醒先读须知，当前同样走 shell 卡）。
2. 报表向导提示词（chat.tpl.html L1011）改为：先把报表结果直接写在回复里（Markdown 表格）；要存成 Excel 文件时先问用户。原句「做完生成一个 Excel 文件给我预览」把 write 步（gen-xlsx 走 shell=必卡）焊死在无人值守段，零卡验收必然破。文件导出移为用户在场的第二拍：卡出现在她刚互动完，60s 内能应答；权限卡哲学（s106/f5 有意保留）不动。这是对 s48「两问出报表」交付形态的显式收窄：报表=答案先到，文件=随后一步。

### 三问归约
① 任务为何死：模型 shell type 读 CSV → ask_before → 60s 超时自动拒 → 工具面上无免卡内容读取通道 → 认输。② 读为何走 shell：goose 无文件内容级 read 工具（v1.46/1.50/1.51 三版一致），唯一免卡的 tree 只给文件名+行数。③ 为何是产品缺陷而非安全摩擦：文件是妻子自己上传给 agent 读的——**上传即同意**；权限系统本意是守护后果性动作，把已同意的读路由进 write 注解工具（shell）是意图误分类。happy path 首步不许要求人在场。

### 为什么不是 B/C（衡量指标：妻子无人值守报表任务成功率）
- B（只改文案教切工作模式）：成功率≈0。硬约束 §2.3 终端用户零技术背景；失败实录里 💡工作模式引导在场没救回来；且整体放宽模式=为一个读问题扩大全部工具授权面，方向反了。
- C（挂 backlog）：默认模式下旗舰承诺每次任务都死；内测期路线=验证优先于扩张、首任务体验即优先级；修法小（一把 vendored 工具+两行文案）。机制证据已 VERIFIED-RUN 齐，无缺口阻塞裁决。

## 边界清单（实现照此；机制不进配置面 §9.4，不加开关）
- **通道**：新 vendored stdio MCP server（包内 node，同 memory-mcp 先例），随包默认启用；能力清单人话名「读文件」+一行解释（R4）。
- **工具名**：`read`——贴模型先验（失败链里模型被引向 read 是自然倾向；goose 自身 hooks 分类器也把 read/cat/view 归读类）。description 写明「读文件内容用它，别用 shell type/cat」。
- **作用域**：仅 `data/artifacts/` 子树（跨工作区可读——工具进程无法可靠感知"当前会话工作区"，整域是可执行的边界；单机单用户无隐私增量）。**不放全安装树**：conf/ 与 data/ 里有 faucet .apikey、供应商密钥，读进上下文=泄进 LLM 请求与日志。
- **返回上限**：默认窗口 400 行且 64KB 先到为准；`offset`/`limit` 行级翻页；回包带总行数与截断说明（对齐 tree「[N]」习惯）。防 50MB 文件糊上下文。
- **文件类型**：不做扩展名白名单（业务文件任意）；内容非 UTF-8/疑似二进制 → 人话错误（xlsx 读不了内容，引导另存 CSV 或走文件面板预览）。
- **错误形态**：越界路径=拒+指明允许的根；文件不存在=拒+引导先 tree 看看；传目录=拒+引导 tree；`..` 归一化后前缀校验，不做字符串匹配。
- **只读纪律**：工具构造上无写 API（QA 负验证项：不存在任何写路径）。

## 风险与降级形态
- goose 升级改 read_only 注解语义 → 退化为 judge 按次（付 LLM 开销）或回归 ask_before 卡=今天的形态，fail-visible、非破坏。缓解：升级检查清单加一条——任何 goose 升级前复跑研究底稿 §4 四臂沙盒探针。
- 上游将来出原生 read → 同名冲突行为未知：同一条升级检查项覆盖（出原生=撤我们的或换名）。
- 误读敏感文件：作用域已排密钥与配置；artifacts 内是用户自己投放给 agent 用的文件，读入上下文即上传本意，无新增暴露面（今天 shell 被批一次能读全盘，面反而更大）。

## 非目标
- 不放宽任何 write 类授权：shell/edit/write/read_image 的卡照旧；`user.always_allow: [shell]` 明确不做。
- 不做 xlsx 内容解析：零卡口径下 xlsx 数据源=已知缺口（人话报错+引导），是否扩 sheet→文本转储等上传构成的真实使用证据再裁。
- 不做第二把工具：目录列举=tree 已免卡；作用域限 artifacts 的写工具（免卡落盘）属独立裁决，本批不碰、不拿注解说谎。
