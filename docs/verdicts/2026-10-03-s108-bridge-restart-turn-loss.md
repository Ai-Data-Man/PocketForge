# S108 裁决：注册桥替换回合孤儿化（iat124）——D+C 组合、secrets 回写加门、B 缓议

裁决 pf-pm 2026-10-03。证据：research/2026-10-03-s108-register-bridge-restart-rca.md（A-E 事实集+三修法约束表，下引 RCA）+ 主控 iat124 净冷装实录 + STATE：s103/S9 断线中性收口 67d90fb（当年有意设计：断线≠失败）+ s103/S7 健康条退出聊天流 2e4faed + s95 F-3 回合孤儿化家族史（B 兜底=04b981e）+ s97 open-when-ready 开窗前 converge 先例（收敛后注册=纯 add+PID 不变）。

**阶段目标一句话：桥可以重启，妻子的话不能石沉大海。**

## 问题陈述与三问

- 谁痛：零基础新用户净装首配后的**第一个回合**（iat124 实录：忙碌条 103 秒后消失，零回复零提示零 banner，WS 静默重连）。「第一次对话就成功」是旗舰故事地基，此形态=首单即石沉大海。频率：净装「配流→立刻用」序列结构性 100% 命中（根因链 RCA 已定案：空值渲染→配流写真值→E1 wrapper 读新 secrets→漂移→只换桥）。不解决的代价：E1b 证明重问可救回内容，救不回「这东西坏了」的第一印象。
- 三问：①何时遇到=净装首配（s99/S3 空值种子→写真值）后第一次 E1 注册；②不用它怎么死磕=用户自担 103 秒静默后自行重问——可行但靠运气，产品零提示=把诊断成本转嫁给最不该承担的人；③做错的代价=C 误报（假悬空）教用户忽略一切提示，D 触发门太宽把日常改档变成频繁断桥（RCA D2-4 机制推断）。

## 裁决一（Q1）：修法组合 = D + C；B 缓议

### D 保存点烧漂移——修，带**双重触发门**

D 是根因侧唯一修法（约束表 :183），但必须收窄为「定义已陈旧才烧」，不许无差别叠加：

- **门 1（值变化门，即裁决二）**：providers 帧只在保存链且三键值真变时写 secrets.env（:5386-5387 加比对门）。面板纯打开=零写入。**converge 只挂在「这次真写盘了」之后**，不挂每次回写。
- **门 2（指纹门）**：桥用 boot 时 `process.env.GOOSE_MODEL/OPENAI_HOST/OPENAI_API_KEY`（=pc 渲染值，RCA D2-6）比对写盘后的 secrets 三键，**陈旧才 spawn converge**（pcExec :2800 先例；arm3 实证自杀式 update 守护端照落）。先例=s94-b2 env 指纹防白热重启（chat-bridge.tpl.js:5392-5393「值一致的热重启是纯噪音」同哲学）。**注意 converge 指纹 ≠ sig2（:5401）**：sig2 刻意不含真实 host（:5399-5400，goose env 恒走桥反代），converge 指纹含真实 host（process-compose.yaml:117-119 三键）——工程师不得复用 sig2。
- **与 hotRestartProvider 的排序**：converge 触发时本轮跳过 hotRestartProvider（换桥已含换 acp）；未触发时保持今日语义（错误帧 :1813→:1740 在飞回合有终态）——这正是绕开 D2-4「错误帧→静默断线」降级的关键：日常同定义改档体验零变化，只有定义真陈旧才付一次换桥。
- **wrapper 失败防御同批（D2-7）**：forge-register 读不到 secrets 三键 → rc≠0+register.log 人话行、**不发 update**（fail-loud）；桥侧前置检查：新 secrets 值非空才 converge（防「烧回空值」漂移放大）。
- **首配时机红利**：首档 add（:5359-5363 needRestart 本就不置）时无任何会话存在（RCA D2-4「非回合窗口」）——converge 落在无人受损的窗口。开窗 converge 失败的坏启动下保存点会替注册付全表重启（D2-5）：接受，时机更好且有界，events 留行。

### C 重连补终态——修，作为 S9 的**窄例外**而非推翻

S9 中性收口（67d90fb）管的是「断线≠失败」的泛断线；本裁决只开一条例外：**有持久化悬空标记的 dangling-turn**。边界如下：

- **标记**：sendTurn 起/止各写一次小文件 `data/turns-inflight.json`（atomicWrite :731 先例；不进 pg——pgStateQ 只有两队列 :492，新表协议面更大）。按 sid 记一条（start ts）；stop 帧/:780 错误帧/回合完成即清；同 sid 新回合开启即覆写（防假悬空，RCA C3 坑①②）。
- **触发点**：subscribe（:5009）挂检查——标记命中本 sid → 补发一帧 → 清标记。无静默时长阈值：重连即判、每标记只提示一次。多窗口同 sid 广播全部订阅者（与 abortInflightTurns 同语义，可接受）。
- **措辞（中性+人话+零技术坐标，对齐 D-3 纪律与 S9 中性哲学）**：「刚才你发的那条消息还没回完，服务刚好重启了一下，这条回答没有完成。可以点『再问一次』，或者直接重新说一遍。」消息流内一条回合级说明，**不弹 banner、不进健康面**（S7 已裁健康条退出聊天流——这是回合终态事实，属会话记录不属连接状态）。
- **重试钮**：给，纯前端（重发该会话最后一条用户消息，复用既有发送路径，桥零改动）——E1b 证明自然重问可行，按钮只是把已验证路径降为一键。可裁掉不返工。
- **S9 本体不动**：无在飞标记的断线→重连仍零提示零 banner（负检查项）。

### B 桥死前告别帧——**本批不做**，留重触发条件

- 覆盖面窄：只救「页面开着且 WS 活着」的窗口；D 落地后其主触发场景（注册漂移换桥）结构性消失，残余=升级流（自有事前告知+2.5s 轮询通道，RCA E）/pc down（用户主动停）/换机——各有归属。
- 成本面新：yaml shutdown.command+新无鉴权自杀端点+PC_TOKEN 校验+down/重启文案分叉（RCA B2 坑①②，:81-84）——为一个稀有残余窗口开新安全面，违反「验证优先于扩张」。
- C 已以秒级延迟覆盖 B 的场景（WS 自动重连+标记补帧），B 的增量≈死前即时 vs 重连后 2 秒，不成比例。
- **重触发条件**：D+C 落地后 events.log 若再现「桥死亡时页面开着、WS 未及重连即关页」的孤儿事件（用户实报），重议 B；否则永久缓议。

## 裁决二（Q2）：:5387 回写无门——**同批修**

最小门=值比对：由活跃档构造 {model,host,key}，与盘上 secrets 三键现值逐一比对，全等则不写（实现可留在原调用点加门，行为=值不变零写入）。理由：漂移积累面比「保存」宽（面板纯打开也写，RCA D1 表 :128）——任何一次随手开面板都会造出「下次注册必换桥」的漂移债；加门后漂移只能由真变更产生，且随即被 D 的 converge 烧掉，漂移寿命从「直到下次注册」坍缩为「直到下次保存」。bootstrap 侧（:145-216 种子/F-11 自愈）零改动。

## 裁决三（Q3）：验收臂（净冷装复跑「配流→立刻装应用」）

1. **核心臂**：净冷装冷启→配流保存→立即对话「帮我搭个小应用」→agent 跑 forge-register。桥重启允许发生；断言妻子面：**悬空通知在注册后 ≤10s 到达**（含桥替换 0.4-1s+WS 重连+subscribe 检查），文案人话零技术坐标，「再问一次」可用且新回合正常（E1b 路径保持）；**零「忙碌条无声消失且无任何说明」形态**。
2. **漂移收敛臂**：保存点 converge 后 boot 指纹=secrets 三键（D 门 2 断言）；**随后 E1 注册=纯 add、桥 PID 不变**（s97 出厂铁证复形态）——即配流后的首个回合不再经历换桥。
3. **permcard/卡数**：同任务 permcard 数与修复前基线一致（本批零权限面改动）；注册仍单命令单卡。
4. **负检查**：①面板纯打开（无保存）→secrets.env 内容与 mtime 不变；②无在飞回合的日常断线→重连零提示零 banner（S9 保持）；③正常完成回合后重连零悬空提示（标记清除正确性）；④日常同定义改档：错误帧路径保持、无额外换桥（D2-4 降级未发生）。
5. **回归臂**：e2e-chat/fuzz/ui-logic 基线不破；converge rc=0 零补跑噪音（v0.9.17 发版门同款判据）；升级路径一臂（升级包覆盖→冷启→标记文件随 data/ PROTECTED 不丢、无假悬空）。

## 非目标（scope 边界确认）

- **不动 pc 上游**（ADR 零 fork 维持；B 的拒绝理由之一同源）。
- **不动 update-runner 升级流**：它有自己的停世界通道+事前告知+轮询（RCA E），且 data/ PROTECTED 天然保护新标记文件。
- **本批不解决「桥重启期间的所有丢帧面」**：只解决 dangling-turn 可见性+漂移源头收窄；页面关闭数日后重开只保证一次性告知，不重建历史工具卡终态。
- 不改 S9 中性收口本体；不做聊天输出过滤/新健康面；不做通用「桥生死事件中心」。

## 成功指标与观察窗

主指标：净冷装核心臂「石沉大海」零发生（沙盒 ≥3 复跑全过）；E1 注册后桥 PID 不变（漂移收敛铁证）。伴生：面板纯打开 secrets 零写入；日常改档断桥次数=0。观察窗：验收沙盒+下一次真机净装/升级使用；events.log 增加 providers converge 与 dangling-notify 事件行（s103/S3 语义），沉淀一个周期后复核 B 的重触发条件与假悬空率。
