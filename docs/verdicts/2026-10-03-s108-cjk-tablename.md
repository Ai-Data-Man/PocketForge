## 问题

谁在痛：**零技术中文妻子**，让 agent 记一张中文命名的表（「家庭开销」）之后的任何一次查看。频率：**条件概率≈1**——hints 全文无表名语言约束且 :14 明文「不猜、不改名」（RCA §四，VERIFIED-DOC），中文任务的自然产出就是中文表名；净冷装首例已发生，dev 树无先例只说明还没人用中文提过需求。三问：何时遇到=建表后打开 🗄️/📊/✨/@ 任一面；不用它怎么死磕=**无出路**——五面齐暗、面板搜索按原名也搜不到、连 tblMiss 降级句都没有（CLI 成功不触发 schemaMiss，RCA §1.2），纯静默；做错的代价=agent 已对妻子承诺「面板里能看到」而面板空=**产品替 agent 说谎**，且命中本产品最坏失败形态「数据丢失误读」（s107 同族）。

关键事实（全引 RCA 底稿行号）：
- **F1 上游零障碍**（VERIFIED-RUN，RCA §二/§三）：faucet REST 写（`_schema` 201）/读（编码 path 200）/CLI（execFile 原生安全）/sqlite 存储对中文表名+中文服务名全链接受。唯一 ASCII 假设=桥 `DB_NAME_RE` 一处（chat-bridge.tpl.js:2477）。
- **F2 一滤五暗**（RCA §1.1/:2550 + §1.2）：overview 表名 filter → 🗄️数据面板/点表名展开/@ 引用菜单/报表向导库表组/✨做过的东西台账全部不可见。
- **F3 同病潜层**：服务名闸门 :2546 同字符集；:2604 硬拒且错文案「表名不对，没有这张表。」把合法存量说成不存在。
- **F4 只扩正则=换一种静默坏**（VERIFIED-RUN，RCA §二）：node 裸中文拼 path 抛 ERR_UNESCAPED_CHARACTERS，被 faucetGet :2501 try 吞成静默 null——:2562/:2575/:2621/:2622 四处 path 拼接必须同批对**变量段**（svc/tbl）补 `encodeURIComponent`（TINFO_TBL/META_TBL 常量段为 ASCII 不必）。CLI 通道零改动。
- **F5 B 侧事实约束**（RCA §五）：与 hints :14 语义冲突；存量中文表名不可自愈（净冷装环境天然再产出）。

## 裁决一（Q1）：选侧 A 全量，拒 B，不做 A+B

**修，侧 A=桥收 Unicode 表名+服务名（同批）+ 四处 encodeURIComponent + :2604 文案人话化 + 滤除处诚实降级（见裁决三）。**

- **产品方向自证**：R4 的存在前提=「条目主名非中文人话（英文表名/包名）时必须附人话解释」——**中文表名本身就是人话，是 R4 语义下的更优终点形态**。强制英文（B）是反向行走：给 agent 加翻译决策（撞 :14「不猜」）、给每张表加回 R4 解释义务，换取的只是下游正则的舒适。
- **B 不修存量**：已发生的不可见数据（沙盒 family.db 一例为证）与净冷装未来产出均依旧被滤——B 是在下游否定上游已证事实（F1）。
- **A 修存量+未来+复发面**（服务名 :2546 同批），改动面小：一正则、四处编码、两处文案、一降级计数。
- **拒 A+B 组合**：A 落地后 B 的可见性收益为零，只剩 hints 语义收紧与翻译张力两笔纯成本。

## 裁决二（Q2）：白名单边界（可测试判据，供工程师落地）

`DB_NAME_RE` **保持单一定义点**（:2477，四闸门共用，安全初衷注释不动——名字来自 faucet 输出，拼 CLI 参数/REST 路径前强制过闸），定义改为：

`/^[\p{L}\p{N}_\-]{1,64}$/u`（node 22 支持 Unicode property escapes；`u` 旗必带）

- **收**：Unicode 字母+Unicode 数字+下划线+连字符。测试向量：`家庭开销`、`表2`、`Budget-26`、`räkneark`、`家庭开销_2026`。ASCII 是严格子集 ⇒ 全 ASCII 存量零回归（行为不变是断言，不是假设）。
- **拒（构造性拒绝=白名单形式，非黑名单枚举）**：`/` `\`（路径分隔）、`.`（含 `..` 穿越/扩展名混淆族）、空格与一切空白（\p{Z}）、控制字符、`%` `?` `#` 引号、零宽/格式字符（\p{Cf} 不属 \p{L}，视觉仿冒名拒）、空串、>64 字符。测试向量各至少一条。
- **安全论证**（沿 :2477 注释义务）：CLI=execFile 无 shell（RCA §二 VERIFIED-RUN 实证）；REST=encodeURIComponent 后 `/` `?` `#` 全被百分号编码且上游 v0.1.12 实测接受（RCA §二）——白名单拒一遍、编码兜一遍，双保险不互替。
- **长度上限 64**：产品级健全界（sqlite 上限远高于此；现存自然名最=4 字符），超限走诚实降级而非静默。

## 裁决三（Q3）：滤除处诚实降级——要做

**结论：加。** 形态：:2550 滤除发生处对被拒表名**计数**并随 overview 载荷携带（**独立字段，不复用 tblMiss**——tblMiss=「库连不上/读不到」，新字段=「名字显示不了」，两因两话，混用必产误导）；🗄️数据 tab 消费为清单顶部一行「有 N 张表的名字显示不了，数据没丢」族文案（对齐 s107 pg-down 裁决先例、madePaint tblMiss 行、qa s83d F-1「误导性空态必须修」）。@ 菜单/向导组**不**加同款行（挑选器内降噪；认知缺口由面板兜底）。理由：即便侧 A 落地后此路径理论不触发（收字符集内全放行），闸门的语义必须是「拒绝必有回声」而非「这次恰好没拒绝」——今天卡的是中文，明天卡的是任何未知形态。

## 边界与非目标（Q4）

- **列名：不动**（确认研究员建议）。列名从不受 DB_NAME_RE 管（dbTableSchema 零校验列名、dbOverview 只搬表名），中文列名端到端畅通已是产品事实（RCA §五姐妹面证据）——无缺陷即无工作。
- :2604 文案人话化：剩余拒绝形态（控制符/超长/分隔符）不得再宣称「没有这张表」——改「这个名字里有显示不了的字符」族，工程师措辞终审。
- **非目标**：存量表迁移/改名（合法存量经侧 A 自然回归五面）；hints 任何语言条款增删；非消费点同族正则（:2363/:2383/:4219 config.yaml 解析、:35/:50 env 键、:2933 脱敏，RCA §1.1 勿误伤清单）；faucet 上游任何改动（零障碍）；pg 驱动下中文表名（RCA §六未测，未来接入另立验证）。
