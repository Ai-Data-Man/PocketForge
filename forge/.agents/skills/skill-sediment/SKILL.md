# 从真实任务沉淀 skill（遵循 agentskills.io 规范）

## 何时沉淀（三个信号任一）
1. 用户纠正过你（"不对，应该用X"）——纠正就是最有价值的知识。
2. 同一个问题你排查了两次才成功——第一次的弯路值得记。
3. 一串多步操作刚完整跑通——下次照做能省时间。

## 提取四要素（从本次会话的真实执行过程，不要凭空编）
1. **步骤**：真正有效的命令/工具调用序列（照抄实际用过的，不是理论最优解）。
2. **纠正**：用户纠正了什么、你最初哪里做错了。
3. **输入输出**：数据长什么样、结果怎么核对。
4. **本项目特有约束**：路径、端口、运行时清单等通用知识覆盖不到的。

## 写出 SKILL.md
- 位置：`.agents/skills/<name>/SKILL.md`（项目级，随文件夹走）。
- 同目录写来源标记 `origin.json`：`{"_schema":1,"source":"self","installed_at":"<ISO时间>"}`（区别自己攒的和外面装的；漏写不影响使用，只会被当成随包技能）。
- name：小写字母数字连字符，必须与目录同名，≤64 字符。
- description：三段式（Use when… / even if… / Do NOT use for…），写触发关键词，≤1024 字符。模型容易漏触发，描述要主动。
- 正文 <500 行：编号步骤 + 坑（footguns）+ **验证步骤**（怎么确认做对了）。
- 只写"通用知识不知道、上次差点做错"的内容；通用常识删除。

## 修订优先于新建
- 先看 `.agents/skills/` 下是否已有近似 skill：有则修订它（更新步骤/补充坑），不新建。
- 发现某 skill 步骤过时：直接改，并在步骤旁注明变更原因一行。

## 验证闭环
- 写完后：向用户复述 skill 的触发场景一句话，征得"对"再收工。
- 下次命中该 skill 时：执行完对比实际，若有出入立即修订。
